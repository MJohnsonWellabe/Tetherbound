## 3. The traps, in the order they will bite you

**The bake fingerprint, four times today.** Any edit to `data/config/vegetation.json`, a
band vegetation file, or `terrain_playground.json` invalidates a committed bake — including
an edit to a `_comment` string. Two rules, and the second is the one nobody writes down:

1. A lane must re-bake and commit the bake in the SAME commit as the config.
2. **That is not enough when two lanes merge.** Each branch is internally consistent and
   the merge is fresh for neither, because the fingerprint covers all the inputs at once.
   Re-bake after merging any two lanes that touched bake inputs, and re-bake BOTH bakes.

This belongs in `docs/AGENT_WORKFLOW.md` and is not there yet. Putting it there is worth
more than repeating it in every lane prompt, which is what I did.

**Harness defects that look exactly like game defects.** Three today, all initially
misfiled as broken game:

- The South Bridge "entombment" was a harness teleport outrunning Terrain3D's
  camera-following collision — the body fell before the ground existed under it.
- The objective-chain "stall" was two assertions pinned to label strings that had never
  existed in `objectives.json`. They could only ever fail, and sat behind a non-gating job.
- `smoke_title_new_game` "carried the old Warden victory into Meadows" — about a game that
  had not left the title screen, because nobody answered the returning-player confirmation.

Before believing a failure describes the game, ask what the harness did to produce it. The
inverse error is also live, so do not assume the harness is wrong either.

**"Verify what changed, not what you changed."** Both of my own mistakes today were this:
the terrain bake above, and a `_restore_satchel` helper that wrote `{}` into empty
inventory slots where `is_full()` tests `stack == null` — leaving the satchel permanently
full and producing eight failures across four apparently unrelated systems.

**A test that mutates shared state must put it back.** `smoke_playground` runs many checks
against one live world. INTERACT-SWEEP's full-satchel check filled the bag and never
restored it.

**CI reality.** A run under five minutes verified nothing — check the code jobs ran. The
`changes` job can queue for 15+ minutes; that is normal, not a hang. `RETRIES` can rescue a
deterministic failure and hide it.

  wasted — reviewing its conflict is how I found that the original fix had raised the

  capture. A lane waiting is a lane stopped; poke it with what you want answered, not just
  "continue".
- **Scope lanes by file ownership.** Seven ran concurrently without collision because each
  owned a disjoint set. The vegetation files are the contended ones: 2.2 and 2.3 both want
  them and must be serialized.
