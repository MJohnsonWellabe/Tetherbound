# R9.1 — Scope the final gameplay-feel polish pass

## Goal
Turn the current placeholder header — **"Input feel, combat cadence, catch feel, camera"** — into a measured, actionable final-polish backlog. Do not treat this as permission to retune every controller/combat variable by taste.

This item is intentionally a **scoping/playtest audit first** because the board contains no concrete defect list beyond those four domains.

## Context
Several concrete issues in these domains already have dedicated prompts/items:
- RG1/RG4/RG6 controller/input lifecycle and UI contracts;
- RG8 combat camera follow/orbit;
- RG15 minimap orientation (not camera feel);
- catching/combat systems already have established mechanics and hard rules.

Verify those landed before creating duplicate tasks. R9.1 should identify the remaining **feel-quality** gaps after correctness work.

## Required playtest matrix
Run current shipped/export-equivalent build on controller-first settings and record a short structured pass through:
1. ordinary exploration movement/camera;
2. gathering/tool use;
3. wild encounter start;
4. quick/charged combat rhythm and switching;
5. catch-aim/throw/result loop;
6. trainer fight;
7. entering/exiting combat back to exploration.

For each, log only player-visible friction with reproduction steps and, where possible, measured values from current configs.

## Scope categories
### Input feel
Assess deadzones, acceleration/deceleration, stick response, sprint/jump transitions, button-edge handling and accidental double actions. Separate **binding correctness** (RG6/TEST2) from analog feel.

### Combat cadence
Assess whether quick attacks, charged attacks, enemy cadence, hit feedback, switching and end-state timing create understandable rhythm. Preserve hard combat canon: real-time piloted creature, no shields/dodge addition, human never fights.

Do not rebalance species broadly unless a cadence defect is demonstrated across the system. Prefer global/tunable cadence fixes where appropriate.

### Catch feel
Assess transition into catch aim, reticle/camera control, throw timing, feedback on hit/miss/shake/result, and return to combat/exploration. Do not change catch probability merely because animation/feedback feels slow unless measured balance evidence supports it.

### Camera feel
Assess exploration orbit responsiveness, collision/spring arm, pitch limits, recenter behavior if any, combat retargeting and transition smoothness. RG8's locked requirement remains: combat follows active creature while retaining normal orbit/look freedom.

## Deliverable
Produce a prioritized list of concrete follow-up items. Each item must include:
- exact symptom and reproduction;
- domain;
- current config/code seam likely responsible;
- whether it is correctness, latency, feedback, tuning or content balance;
- proposed smallest change;
- acceptance test/measurement;
- risk to existing behavior.

Rank P0/P1/P2 by how strongly it affects willingness to keep playing, not by implementation convenience.

If a domain feels good on current main, say so and do not manufacture work.

## Measurement
Use current data/config values as baselines. Where useful record input-to-visible-response frames, attack intervals, catch transition durations and camera response curves. Do not require laboratory precision; measurements are to prevent vague "make it snappier" tasks.

## Preserve
- controller-first Ally target;
- current combat hard rules;
- five-creature cap;
- existing catching legality;
- no new mechanics disguised as polish.

## Acceptance criteria
1. All four placeholder domains are played on current main.
2. Already-solved dedicated backlog defects are not refiled without current reproduction.
3. Remaining problems are expressed as concrete reproducible tasks with acceptance criteria.
4. Tuning proposals cite current values and keep changes data-driven.
5. No shield/dodge/weapon/major traversal mechanic is invented.
6. If little remains, R9.1 can legitimately close with a short "no material gap" report.

## Definition of done
R9.1 has transformed from a vague polish heading into a small evidence-based queue of only the gameplay-feel changes the current build actually needs.
