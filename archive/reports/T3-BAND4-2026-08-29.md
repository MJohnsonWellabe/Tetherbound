# T3-BAND4 -- closing Band 4's authored-content gaps, 2026-08-29

Branch `ralph/T3-BAND4`, from `ralph/T3-CADENCE`. Implements the top three
priorities of `ralph/reports/finding-post-tournament-cadence-2026-08-29.md`
against `docs/owner-direction/TETHERBOUND_MEADOWS_MIDGAME_FUN_REBUILD.md`
(read off `ralph/OWNER-DIRECTION-0829`, which this branch does not carry --
see "environment notes" below). Bounded to ~90 minutes; item 4 (camp/rest,
lowest priority in the brief) was not reached.

## What the finding found

Raw dead-travel already passed everywhere (worst gap 165m/41s, chapter-wide).
The real problem was authored-content density once ambient wildlife (87% of
all POIs) is stripped out: Band 4 held 4 of the run's 5 worst authored gaps,
worst 1,064m (~4.4min), against a chapter-wide-passing 11 authored POIs over
3,436m (312m/~78s average spacing).

## What this branch did

Four beats, in the finding's own priority order, each justified against
`MEADOWS_MEADOWS_MIDGAME_FUN_REBUILD.md` section 5's rule (pays into team
strength/choice/prep/discovery/story, not raw prop density):

1. **Band3/4 seam (was the run's single biggest authored gap, 1,064m).** A
   tree-line "Ironwood grove" beat right where the region's own name-tier
   resource starts: two Ironwood harvest trees + a fiber node
   (`data/config/bands/band4_upper_meadows_ironwood/harvest.json` 4011-4013),
   clustered rather than scattered, same TwistedTree_4/pale-variant choice
   the existing stand already uses (avoids the documented "red leak" bug).
   Beside it, a solitary elder Meadowhart -- alpha, non-starter, +4
   levels/1.3x scale (`spawns.json` 4075) -- the chapter's own named riding
   creature (`docs/MEADOWS_PROGRESSION_SPEC.md` Band 4), so the region's
   entry moment doubles as an on-sight roster temptation
   (owner-direction section 11's test) rather than a stat-sheet one.

2. **Band4/5 seam (was 852m, the run's second-worst).** A new ruined
   watchtower landmark (`scripts/world/watchtower_landmark.gd`, placeholder
   primitive geometry -- matching `signpost.gd`'s own documented house
   convention and CLAUDE.md's Meshy-generation gate, which this content does
   not clear without owner reference art) built into `playground_world.gd`
   the same way the Sigil Gate is. `docs/MEADOWS_PROGRESSION_SPEC.md`'s own
   Band 4 area list already names "ruined watchtower" as regional identity;
   nothing had ever built it. A Water TM (`tm_riptide_lance`) sits at its
   base as the visible reward, plus a map pin (`the_broken_tower`,
   `data/config/map_landmarks.json`) -- ownership note: this lane placed the
   landmark and its reward; ownership of landmark *presentation* is
   `T1-REGIONS`'s per the brief, and this structure is intentionally left
   plain for that lane to build on rather than pre-empt.

3. **Two interior gaps before Captains Halder and Vess (818m, 768m).**
   Before Halder (Ground-focused): an independent wayside trainer, Juno --
   `config_key: villager_ranger` (reuses the installed rig, no new mesh),
   a warm-up Ground-leaning team one level under Halder's own weakest
   (`trainers.json` 4001, dialogue added to `data/dialogue/trainers.json`).
   Before Vess (Air-focused): an Air TM, `tm_wind_blade` -- direct
   preparation for that fight's own type, not just XP.

## A real siting bug, caught and fixed by re-running the same instrument

The first pass measured grove/Meadowhart candidate sites for local
height/slope only (`tools/_probe_t3band4_sites.gd`) and never checked
distance to the actual corridor spine. Two of three new harvest nodes and
the alpha Meadowhart landed 34-76m off the route -- past the probe's own
30m notice radius -- so the very re-run meant to prove the gap closed
instead proved it hadn't (band4 `met` barely moved). Re-sited all four
1.9-13.0m off the spine on the same flat shelf
(`tools/_probe_t3band4_grove2.gd`), re-ran the probe, confirmed the gap
actually closed (see table above). Recorded here rather than silently
fixed, per CLAUDE.md's "record meaningful findings/decisions."

## Environment notes for the next lane in this container

- No Godot binary and no `.godot/` import cache existed in this container.
  Fetched 4.7-stable matching CI's `GODOT_VERSION` (`~/godot-bin/godot`).
- **The import cache is load-bearing, not optional.** Before it existed,
  every scene-booting script (including this corridor probe) failed
  `class_name` resolution (`SCRIPT ERROR: Identifier "UITokens" not
  declared`) and silently returned a near-empty world (`met=1` across the
  whole 11.5km chapter) -- Godot did not treat this as fatal, it just booted
  a broken scene and returned exit 0. Any before/after number produced
  before running `godot --headless --path . --import` (cold, then verify,
  matching `.github/workflows/ci.yml`'s own two-pass job) is not trustworthy
  evidence, even if the command exits cleanly.
- `tests/test_harvest.gd` hangs in this container at
  `test_a_gltf_model_builds_a_real_populated_mesh_not_a_dead_assignment`
  (the first test after `test_marking_is_deterministic_for_the_same_seed`,
  alphabetically/definition-order), independent of this branch's changes --
  reproduces identically before and after this branch's diff, and the
  earlier structural check in the same file
  (`test_every_authored_harvest_spot_is_real_and_reachable`) already passed
  for the new nodes. Likely a headless-rendering limitation loading a real
  `.gltf`; not investigated further, out of this lane's scope.
- The five other data-integrity suites this branch's changes touch
  (`test_trainers_data`, `test_spawns_data`, `test_map_landmarks`,
  `test_band_content`, `test_band_dialogue`) run clean and fast: 90 tests,
  3830 assertions, 0 failed, both before and after the siting fix.
- `docs/owner-direction/TETHERBOUND_MEADOWS_MIDGAME_FUN_REBUILD.md`, cited
  throughout this pass's own brief, does not exist on `ralph/T3-CADENCE` or
  `main` -- only on `ralph/OWNER-DIRECTION-0829`. Read via
  `git show origin/ralph/OWNER-DIRECTION-0829:docs/owner-direction/...`
  rather than merged into this branch, since the brief did not ask this lane
  to bring that branch in and `ralph/T3-BRIDGE` (the sibling lane branched
  from the same base) hadn't either. Flagging for whoever reconciles these
  branches: every Track 3 lane is currently reading a doc none of them

## Not reached

lowest priority in the brief) was not started; the time budget went to
verifying the first three items were real rather than config-shaped. A
`camp.gd` instance is the game's one real rest mechanic and is
player-built, not band-authored -- Band 1 and Band 3 both solved this with
prop-cluster dressing that reads as a camp without being one
(`props.json`'s `trail_camp`/picket-camp clusters, "the game has exactly
one rest structure and this is not a second one"); the same pattern would
apply here rather than inventing new mechanics.
