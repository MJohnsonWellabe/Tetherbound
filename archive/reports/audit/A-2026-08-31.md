# AUDIT-A — Player-voice acceptance (A1–A11)

**Lane:** `AUDIT-A`, branch `ralph/AUDIT-A`.
**Audited ref:** `main` at **453107fb** (the LAND-0830J consolidation, landed
2026-08-30).
**Governing instruction:** `ralph/NEXT_COORDINATOR_FULL_STATE_AUDIT.md`;
section under audit: `ralph/MEADOWS_EXIT_CRITERION.md` §A (A1–A11), the
player-voice acceptance list sourced from `docs/TETHERBOUND_GAME_VISION.md` §10.

**Rules honoured:** no game-code changes were made or considered; nothing
under `scripts/`, `scenes/`, `data/`, `assets/` was touched. This report is
analysis and one new document proposal only. A config-level assertion is not
treated as evidence a player reached anything; a played path is. "Cannot be
determined" is used wherever that is the honest answer, not filled in with a
guess.

**Why this section reads differently from B–K.** A1–A11 are the one-sentence
test's own eleven clauses — statements about what a *player* would say after
finishing the chapter. No unit test, no config check, and no frame contact
sheet can settle a first-person claim like "I cared." This report does not
attempt per-item PASS/FAIL verdicts the way a terrain or NPC section can. Per
the governing instruction, its actual job is the triage: for each of the
eleven, (1) what signal in the GATE-F-FULL instrumented playthrough's own
output would count as evidence, (2) which need a human at the controls, and
(3) which nobody currently has any way to measure at all. List (3) is flagged
by the instruction as the most valuable output of this lane, and it is longer
than a first read of the exit-criterion doc suggests — see §3.

## 0. What currently exists to answer any of this

Three instruments exist in the repo today that could bear on A1–A11. All
three were inspected directly, not taken on report.

### 0.1 The GATE-F-FULL instrumented journey (Lane 12, in parallel with this one)

`ralph/GATE_F_MASTER_PROTOCOL.md` defines a very rich telemetry schema
(`events.jsonl`, `route.csv`, `notes/<segment>.md`, `shots/manifest.json`) that
an agent operator produces while playing the chapter through Godot's real
input system on production paths. Every field is read from **live game
state** (`ralph/GATE_F_MASTER_PROTOCOL.md` §C.5) — real quest log, real party,
real vitals — never a parallel reimplementation, and `tests/test_gate_f_rig.gd`
mechanically fails the suite if a schema event type is never emitted and never
explicitly marked `not-instrumented` (§C.1/CD-6). That guard is currently
green: the 2026-08-30 full unit suite run (`ralph/reports/handover-GATE-F-RUN7-2026-08-30.md`
§7) shows 1661 tests passing with exactly 2 pre-existing, unrelated failures.
So the schema itself is sound and complete as an instrument.

**What is actually on disk today is far short of what the schema can carry.**
The furthest any run has gotten is `ralph/reports/gate-f-run7/`: S01 (13
PASS/0 FAIL) and S02 (79 PASS/3 FAIL), a healthy fresh-save exit at
`ralph/reports/gate-f-run7/S02/saves/S02-exit.json` — party of 2
(Ripplet L3, Bramblebun L2), `road_gate_open` set. That is roughly the
chapter's first 20 minutes out of a 3–4 hour target. **S03 through S10e —
the village ladder, the tournament, all five Meadows bands, the Warrens, the
Stronghold, the Warden fight, the legendary release, and the post-win world
healing — have never completed in a single chained run.** Every one of
A1–A11 is a whole-chapter claim (roster pressure *before* the legendary,
the Warden as *culmination*, the world *after* the win), so as of this
writing **the honest verdict on every single item below is "cannot be
determined — insufficient run coverage,"** independent of whether an
instrument exists for it. The per-item analysis that follows is about what
signal *would* decide each item **once Lane 12's run reaches the segment
that carries it** — it is a specification for a reader who has not yet seen
that run, not a claim that the signal has been observed.

### 0.2 Owner playtests

`ralph/OWNER_PLAYTEST_2026-08-18/21/23/28/30.md` are real, and under
`CLAUDE.md` precedence they outrank any test or telemetry that contradicts
them. But every one of them is an **unstructured complaint log** — the owner
plays and reports what broke or annoyed him (the gate doesn't gate, the key
doesn't glow, catching is too hard). None of the five documents contains a
question, prompt, or checklist shaped like any of A1–A11. This matters for
§2 below: "get the owner to play" is necessary but **not sufficient** to
answer these eleven, because nothing currently asks him. See §3.4.

### 0.3 `visual-judge`

`.claude/skills/visual-judge/SKILL.md` is a blind sub-agent critique against
`docs/reference/tetherbound-meadows-keyart.png` and the Palworld reference
set, answering two fixed bar questions about art direction (palette,
density, silhouette clarity, whether a fight looks like an event). It is a
**single-sheet, single-timepoint** instrument as written: it was not built to
compare band A against band B for distinctness, or a location's before/after
state for "did this look like it changed." It is directly reusable for A5
and A11 with a **different contact sheet and a reworded question**, not with
its default invocation — see A5/A11 below.

## 1. Per-item analysis

Each item: the exact signal that would decide it once the run exists, current
state, and what closing it costs.

### A1 — "I understood what I was trying to become strong enough to do"

**[GATE-F-EVIDENCEABLE].** `ralph/GATE_F_MASTER_PROTOCOL.md` §E.5 is built
almost exactly for this: at each of the 27 main-chain objectives
(`data/progression/objectives.json`), the operator records objective wording
verbatim, whether it states **what** and **where**, visible landmarks from
the player's position, minimap/full-map usefulness at that point, and a
navigation decision made from player-visible information alone, logged as a
`note` event before any authored coordinate is consulted (a real instance of
this shape already exists at `ralph/reports/gate-f-run7/S02/telemetry/events.jsonl`
line 1: an S02 `note` event carrying `objective.id: "opening:beat:choose"`,
`objective.text: "Go down and hear Grandpa out."`). The signal: fraction of
27 objectives where the operator could state what/where from visible
information before consulting the coordinate table, plus the count of
`note` events reading "could not determine where to go."
**Caveat (stated by the protocol itself, §E.5):** the operator is a scripted
agent that has the coordinates before it starts, so a clean pass here is
weaker evidence than a genuinely blind human first-timer — it will catch
gross failures (objectives naming nothing findable) but not subtler
confusion a first-time player would feel.
**Current verdict: cannot be determined.** Only objectives 1–5 of 27 have
been reached (S01/S02). **Cost to close:** zero new engineering — this is
pure run coverage. Once Lane 12's chain reaches S10, the answer is a
tabulation over existing `note` events already in the schema.

### A2 — "I cared which creatures made my five"

**[NO PROXY EXISTS] / [NEEDS HUMAN], see §3.1.** This is a felt attachment
claim. The closest thing to a proxy in the schema is the `bond` field on
each party member (`ralph/reports/gate-f-run7/S02/saves/S02-exit.json`
shows `bond: 0` and `bond: 15` for the two starters) and swap-frequency from
`combat_switch`/party-cycle events — but `bond` is a **game mechanic's own
stat**, produced by the game's bond formula, not a measurement of the
player's felt preference; an agent operator has no preference to record in
the first place, so no run of the current harness, however complete, can
answer this. See §3.

### A3 — "I repeatedly found reasons to fight, catch, explore, gather and prepare"

**[GATE-F-EVIDENCEABLE].** Direct signal: counts of `combat_start`,
`catch_throw`, `gather`, `craft`, `build_place` events per unit play time
(`t` field, play clock per §H.2) across S02–S10, cross-referenced against
`dead_travel_m` gaps in `route.csv`. "No dead stretches" reduces to: no
window of the journey with zero qualifying events longer than the §D
threshold (≥250 m dead-travel is a finding, 150–250 m a watch item — already
defined mechanically in §D of the protocol). **Current verdict: cannot be
determined** — only the opening 20 minutes exist, which is too short a
window to speak to "repeatedly," a whole-chapter claim. **Cost to close:**
zero new engineering; needs the chain to run S03–S10.

### A4 — "Building and rest mattered because they supported the journey"

**[GATE-F-EVIDENCEABLE, with a defined causal proxy].** The schema carries
`rest`/`feed` events and party `hp`/`fainted`/`nourishment` state at every
tick. "Mattered" is operationalized as: did a `rest` or `feed` event
precede a subsequent combat performance improvement (HP margin, fewer
faints) relative to the pre-rest state, and did the journey ever reach a
state where a creature was actually near-fainted or unrested going into a
fight it then handled better after resting/feeding. This is close to
`MEADOWS_EXIT_CRITERION.md` H3/H4's own evidence path (T5-CARE already
produced partial evidence there: placement, satiety and bed rest pass per
the coordinator's known-open-findings list). **Current verdict: cannot be
determined** from this run (S01/S02 predate any rest/feed event; S03 is
where the three creature beds get built per the segment table).
**Caveat:** this only shows rest/feed **had an effect**, not that the
*player* experienced it as mattering — the felt layer still wants a human
(§2). **Cost to close:** zero new engineering; needs S03 onward, plus a
short correlation script (a few hours) over existing `events.jsonl` once the
run exists — no new instrumentation is required, only analysis.

### A5 — "Different parts of the Meadows felt like distinct real places"

**[GATE-F-EVIDENCEABLE, but needs a second instrument beyond default
visual-judge] — verifier is explicitly named "blind judge" in the exit
criterion itself.** `ralph/GATE_F_MASTER_PROTOCOL.md` §E.7/§G already
schedules the raw material: per-region arrival, gameplay, landmark,
terrain-close, and ecology frames for all eleven named regions
(`GF-03` through `GF-12`, `GF-AUD-<region>`), taken at the state the journey
or the X07 DIAG audit actually reaches. **What is missing is the judge
pass itself, framed for this specific question.** `.claude/skills/visual-judge`
as written (§0.3 above) answers two fixed bar questions against a keyart/Palworld
reference — it is not, by default, asked "do band 1 and band 4 read as the
same place." Closing this needs: (a) the regional frame set from Lane 12 or
PHOTO-EVERYTHING, (b) a contact sheet grouped by region, (c) one blind
sub-agent pass with the reworded question "could you tell these frames
apart as different places, and if so what makes each recognizable" — the
existing mechanism (blind agent, no design context, `docs/reference/`
withheld or supplied per the skill's own separation rule) is directly
reusable, only the prompt changes. **Current verdict: cannot be determined**
— no full regional frame set exists yet (capture lane has not run past
S01/S02), and no distinctness-framed judge pass has been run against any
existing frames either. This is also flagged as **an open defect already**
elsewhere in the exit criterion: E2 (Meadows Hall, "in flight") and D1/D5/D6
("flat green test environment," "engineered canal," visible seams) are all
per-region identity defects a strict A5 verdict would have to weigh even
after the frames exist. **Cost to close:** the frame capture is Lane
12/13's existing scope (no new work); the reworded judge pass is small —
under an hour once frames exist, since it reuses the skill's own mechanism.

### A6 — "I was tempted off the direct route"

**[GATE-F-EVIDENCEABLE, weaker fidelity].** Signal: `landmark_discover`
events and `note`-logged navigation decisions (§E.5) that fall **off** the
named Route IDs (RT-01…RT-13, `ralph/GATE_F_MASTER_PROTOCOL.md` §D) but
still occurred, distinguished from forced detours by the operator's own
pre-registered routing note ("objective says X; map shows Y; choosing route
Z because…"). The exit criterion's own G8 (optional-content density, "6–10
activities") and G9 ("every detour pays") are the same underlying signal
from a different angle — this item and those two should be read together
rather than re-derived independently. **Caveat:** an agent operator does not
get "tempted" the way a curious human does; a scripted detour proves the
detour *exists and pays off*, not that a first-time player would notice and
choose it unprompted. That gap does not close without a human (§2).
**Current verdict: cannot be determined** — no journey segment past the
opening has run, and the opening (S01/S02) is a fixed, non-optional intro
with essentially no branch points to test this against. **Cost to close:**
zero new engineering for the mechanical half (needs S05–S09, where the
optional-discovery content actually lives); the felt-temptation half needs
a human regardless of run completeness.

### A7 — "I did not spend long periods running through empty scenery"

**[GATE-F-EVIDENCEABLE — the cleanest item in this section].** Direct,
already-instrumented, already-thresholded: `dead_travel_m` is a first-class
`route.csv` column (`ralph/GATE_F_MASTER_PROTOCOL.md` §C.2), reset on any
POI within 30 m or any meaningful interaction (§F's mechanical definitions),
sampled at 2 Hz of **play** time (not wall time — §H.2's fix for the clock
bug that inflated every duration before 2026-08-28 is already landed and in
effect for run7's data). Thresholds are pre-defined: any interval ≥ 250 m is
a finding, 150–250 m a watch item (§D). A working sample of this column
already exists at `ralph/reports/gate-f-run7/S02/telemetry/route.csv` (562
rows; observed `dead_travel_m` values up to ~40 m within the opening, well
under threshold, which is expected — S02 is the tutorial corridor, not open
Meadows). **Current verdict: cannot be determined for the chapter as a
whole** — the long open stretches this item is actually about (bands 1–5,
RT-03 through RT-11) have not been played. **Cost to close:** zero new
engineering; this closes automatically as soon as the chain reaches S05
onward, and needs no separate analysis step beyond a threshold scan already
specified in the protocol.

### A8 — "My team at the end felt earned and different from my team at the beginning"

**[GATE-F-EVIDENCEABLE for the objective half].** Direct: diff the party
array between the earliest available exit save and the finale exit save.
The exact structure is on disk now — `ralph/reports/gate-f-run7/S02/saves/S02-exit.json`
`party` array carries `species_id`, `level`, `xp`, `bond`,
`battles_fought`, `levels_gained_with_you`, `move_quick`/`move_charged`,

the same felt-experience gap as A2, though weaker: an objective diff that
shows real progression is at least consistent with "earned," whereas a diff
showing no real change would be a clean, unambiguous FAIL regardless of any
human's opinion. **Current verdict: cannot be determined** — no finale save
exists (S10a–e unreached); the only party snapshot on disk is the S02
starting roster. **Cost to close:** zero new engineering; a diff script
against the two save JSONs, once both exist, is trivial (well under an
hour).

### A10 — "Freeing the legendary and choosing the final five mattered"

### 2.2 Which need a human at the controls

Every item in §1 above has a felt-experience residue the telemetry cannot
close on its own, so in the strict sense all eleven eventually want the
owner's own play. But three are qualitatively different — the mechanical
proxy is either absent or clearly insufficient on its own, so a human
verdict is not a nice-to-have confirmation but the *only* route to an
answer:

- **A2** — "cared." No mechanical proxy exists (§1, §3.1).
- **A9** — "felt like the culmination." Proxies exist for the mechanics of
  the fight, not for its felt weight relative to the rest of the chapter.
- **A10** — "mattered... enough to hurt." Same shape as A9: the ceremony's
  mechanics can be verified, its emotional weight cannot.

For the rest (A1, A3–A8, A11), a complete, well-instrumented GATE-F-FULL run
plus the two proposed judge passes would give a strong, specific,
evidence-backed provisional answer — but per `MEADOWS_EXIT_CRITERION.md`'s
own one-sentence test ("a fresh player... through their actions, not a
survey"), the agent operator is not that fresh player, and §E.5 says so of
itself. A confident final "yes" on any of them should still be checked
against one real owner playthrough before this project calls the Meadows
finished, exactly as `ralph/GATE_F_MASTER_PROTOCOL.md` §0 tags every
twitch-feel/device-level claim `[OWNER-ONLY]` throughout the rest of the
document.

## 3. What nobody can currently measure, and why "get the owner to play" is not the full fix

### 3.1 A2 — "I cared which creatures made my five"

No instrument, proxy, or even a *design* for one exists anywhere in the
repo. The `bond` stat (`data/...` party schema, visible in
`gate-f-run7/S02/saves/S02-exit.json`) measures the **game's** model of
attachment (an accruing number), not the **player's** felt attachment to a
specific creature — a player could have a maxed bond stat on a creature they
would drop without a second thought, or a low-bond creature they would
fight to keep, and nothing distinguishes those cases today. Behavioral
proxies that *could* be built but do not exist yet: swap/deploy frequency
per creature (already loggable from existing `combat_switch`/party-cycle
events, just never aggregated this way), or which creature the player
chooses to lead with unprompted. None of these were designed with this
question in mind, so none should be read as answering it without a decision
to build and validate them first.

### 3.2 A9 and A10 — "felt like the culmination" / "mattered... enough to hurt"

Same shape as A2: no instrument, no proxy design, nothing. The one thing
adjacent to a proxy — CB-06's Warden combat telemetry, the release
ceremony's own mechanical checklist — measures whether the **content**
exists and fires correctly, not whether it lands emotionally. A fight can
have a perfect HP-margin curve and camera stability and still not feel like
a culmination; a ceremony can reference every party member by name and
still not hurt. Nothing currently attempts to close that gap, and the exit
criterion's own language (F4's "an exam, not an HP pool," F5's "carries
enough history to hurt") shows the project already knows this is the real
bar — it has just never been operationalized into anything measurable.

### 3.3 The felt-experience residue on every other item

Even where §1/§2.1 name a solid mechanical signal (A1, A3–A8, A11), each
retains a felt component with literally no instrument reaching it:
"understood" (A1) vs. merely "had the information available"; "repeatedly
found reasons" (A3) vs. "the events exist in the log"; "tempted" (A6) vs.
"took a scripted detour." An agent operator cannot report confusion,
boredom, or delight because it does not experience them; it can only
report what happened, not how it felt to happen. This is stated, not to
relitigate every item as unmeasurable, but because a downstream reader
should not read "A7: cannot be determined, needs S05–S09" and assume a
completed run makes it a clean PASS/FAIL — even a completed run leaves the
felt residue exactly where this paragraph says it is.

### 3.4 The deeper gap: even the human-at-controls path has no instrument today

§0.2 already showed the five existing owner-playtest documents are
unstructured complaint logs, not a directed elicitation of A1–A11. This
means "have the owner play it" is **not**, by itself, a plan that produces
an answer to any of these eleven — nothing currently asks him. Sitting him
down for a full chapter clear and writing down whatever he happens to say
would very likely surface some of these (frustration reads as easily as
delight in his existing playtests), but it does not reliably cover all
eleven, and it conflates "he didn't mention it" with "it didn't happen" —
exactly the false-negative risk `ralph/OWNER_PLAYTEST_2026-08-30.md`'s own
framing ("a current owner reproduction reopens an item... even if a
regression test passes") should make this project wary of on the flip
side.

**The cheap fix, costed:** a short, direct post-play interview template —
eleven questions, one per A-item, worded close to the exit criterion's own
first-person phrasing ("Did you understand what you were trying to become
strong enough to do?" / "Did you care which creatures made your five, and
which ones, and why?" / "Did the Warden feel like the climax of everything
before it, or just another fight?") — handed to the owner immediately after
one full chapter clear on the ROG Ally, answers recorded verbatim rather
than summarized. This is genuinely cheap: writing the template is under an
hour (a draft is one paragraph away from what §1 above already states per
item), and it costs the owner nothing beyond the play session Gate F
already needs from him for every `[OWNER-ONLY]` item elsewhere in the
protocol (device frame rate, twitch feel, and now this). It does not
replace GATE-F-FULL's telemetry — it is the one instrument that can close
A2, A9, and A10, and it strengthens every other item's verdict from
"agent-plausible" to "player-confirmed." No such template exists today; it
is proposed here, not written, because writing it is a documentation task
this lane could do but a full elicitation instrument for an as-yet-unplayed
ending deserves the coordinator's or Fable's sign-off on its exact
wording before it is the thing measuring the chapter's success.
