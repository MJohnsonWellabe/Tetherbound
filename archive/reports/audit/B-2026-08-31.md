## B1 — Every creature reads as a distinct designed animal

**Verdict: MIXED.** The exit criterion's own named defect (the four Aspect
variants sharing one mirrored decal mask) is fixed and independently
confirmed on-frame. But a fresh, out-of-context blind pass run this session

## B2 — Visually prominent against habitat (no creature vanishing into grass)

**Verdict: OPEN, and now freshly measured against the current build — the
mesh swap that was supposed to address this has not fixed it.** The exit
criterion's own 1.08:1 figure was stale (see below); this session's own
re-measurement puts the current build in the same range or worse.

The 1.08:1 luminance figure the exit criterion cites is real but is not
current. `data/creatures/species.json`'s own `bramblebun` block (`_comment_
field_rim_0828`) carries the measurement verbatim:
`tools/_probe_grass_separation.gd` rendered Bramblebun four ways (height
0.78/0.96 × rim 0/0.22) from one fixed camera in real grass at throwing range,
and found the rim mechanism a no-op on this self-lit material: luminance
contrast 1.15→1.14 at the old height, **1.08→1.06 at the shipped height**, with
`field_rim` deliberately left at `0.0` because it does not register on this
material. That measurement is real, but it was taken **before** Bramblebun's
model was swapped to `bramblebun_redesign` (T1-CREATURE-RIG, same-day,
confirmed live at `species.json`'s `bramblebun.placeholder.model`) and before
its height moved 0.96→1.00 (T3-CREATURES). **No handover after the mesh swap
re-measures grass luminance contrast for Bramblebun.**

**This session ran a fresh measurement** with the same instrument
(`tools/_probe_grass_separation.gd`) against the current build, to close that
gap rather than just note it. Result: **the redesigned mesh is not better
separated from the grass field than the old one — by this measurement it is
slightly worse.** Full method and numbers in the Addendum below.

**Independent observation, this session, on a different species:** viewing
`ralph/reports/T1-RIG-3/shots/sparkit-a.png` (a real in-world frame, real
grass, produced this same T1-RIG-3 lane for an unrelated purpose — verifying
animation, not luminance) directly: Sparkit's tan/gold coat sits at a similar
value to the sunlit grass and dirt path around it and is materially harder to
pick out at a glance than Frostclaw is in the adjacent frame
(`frostclaw-a.png`, pale grey-blue against dark green, high contrast). This is
an eyeball observation, not a measurement — no probe has been run against
Sparkit — but it suggests B2 is not a single-species problem confined to
Bramblebun.

**Closing cost:** the cheap half is already done this session — the number
exists now, and it says the redesign did not solve the problem. Closing it
for real is a content decision: a genuine albedo/value change to the mesh
(the rim lever is already proven a no-op on this self-lit material by the
original lane's own four-way test, and this session's numbers are
consistent with that still being true on the new mesh), or a size push
larger than the "modest" 4% step D-0.96 was aimed at avoiding — either way
an owner- or art-lane call, not a config tweak. A roster-wide luminance
census (all 25 species against their authored habitat) does not exist and
would be a half-day capture-and-measure task with the existing probe
generalised to take a species argument and read `species.json`'s live
height instead of the two hardcoded test values.

## B3 — Rarity legible on sight (common / uncommon / rare / alpha)

**Verdict: FAILS for three of the four named tiers. Only alpha has a
presentation mechanism; common/uncommon/rare carry zero visual distinction.**

This is a direct code-level finding, not a rendering judgement, and I verified
it by reading the code rather than trusting a description of it:

- `data/config/spawn_tables.json` defines exactly three tier strings —
  `common`, `uncommon`, `rare` (confirmed by walking the loaded JSON and
  collecting every `"tier"` value present: `{'common', 'rare', 'uncommon'}`).
  These tiers control **spawn weight only**.
- `scripts/creatures/creature_body.gd::_refresh_shiny_tint()` (line 535-548)
  is the single function that decides a creature's presentation, and it
  branches on exactly two boolean fields — `shiny` and `alpha` — never on
  `tier` or any rarity string. I grepped every file under `scripts/creatures/`
  for `tier` and found no reader outside a doc-comment.
- **Alpha's presentation is real and substantial**: a per-species repainted
  `*_alpha.png` colourway where authored, a rim-light on the silhouette edge
  (`_apply_alpha_presence()`, `ALPHA_RIM_STRENGTH`), a drifting particle aura
  (`scripts/creatures/alpha_aura.gd`), and a mandatory gameplay size increase
  (`apply_size_multiplier`, tested by `tests/test_wild_alphas.gd::
  test_every_alpha_is_visibly_bigger`, which I ran this session — passes).
  This is exactly the kind of "presentation, not just a stat block"
  differentiation the criterion asks for, but it is the **only** tier that has
  it.
- `common`/`uncommon`/`rare` have no code path that touches colour, scale, VFX
  or any other presentation channel. A common Terrapup and a rare-tier
  creature of identical species render identically.

I ran the full `test_wild_alphas.gd` suite (6 tests, all passing) and read the
four `test_creature_*.gd` files — none contain a visual/VFX-presence
assertion of any kind for any tier. All creature-visual verification in this
repo is judge-pass or handover-eyeball only, never pinned by a test, which is
consistent with why the same visual defects (the D18/D19 regressions above)
keep recurring rather than failing CI.

**Closing cost:** this is a design-and-code gap, not a content gap — the
`tier` field already exists in data and needs a code path, e.g. a per-tier
material tint/rim tier below alpha's own, or a decision that spawn-tier rarity
is deliberately invisible and only the individual-roll axes (shiny/alpha)
should be legible (in which case the exit criterion's own wording needs
correcting, not the code). Either way this needs an owner decision before it
is a wiring task — implementing a guess at "what uncommon should look like"
without one risks the same kind of silent design invention `CLAUDE.md` asks
lanes to avoid.

## B4 — Sits correctly in the world (ground, water, contact shadow)

**Verdict: MIXED. Slope-embedding is fixed and I confirm the fix's reasoning
holds; flat/zero-volume embedding, open-water non-demonstration and general
outdoor contact shadows remain open, and nobody has re-photographed Creek
Hollow since the ground fix landed.**

JUDGE-3 §2b photographed two failure modes at Creek Hollow, both real and
both still present in the committed frame I opened myself
(`ralph/reports/JUDGE-3/shots/creek-hollow/far_water_edge-CROP-embedded.png`):
one creature "lying completely flat with zero volume" (visually confirmed — a
splayed purple/blue smear on the grass with no legs, no depth, no shadow) and
one "sunk into the slope from the hindquarters back."

- **The slope-seating half is fixed**, and the fix is correctly scoped: `T1-
  GROUND-3` (`handover-T1-GROUND-3-2026-08-30.md`) root-caused it to `place_on_
  ground` sampling a single ground point, replaced with `_seat_over_footprint`
  (four axis samples, seats on the highest ground under the footprint — can
  only raise a body, never lower it). The same lane's own handover explicitly
  declines to claim this covers the "lying completely flat with zero volume"
  case: *"That is a different and larger symptom than slope seating explains,
  and I would rather leave it open than claim the seat fix covers it."* I take
  that self-assessment at face value rather than rounding it up.
- **General contact shadows are correctly configured, not broken.** `T1-LIGHT`
  checked the actual mechanism (Godot's directional sun ships
  `shadow_enabled: true` by default, SSAO is on in `art.json`, no creature or
  VFX script sets a `cull_mask`/`light_cull_mask` that would exclude a
  creature body from shadow casting — grepped `scripts/creatures/`,
  `scripts/combat/`, `scripts/world/encounter_director.gd` directly) and
  concluded the missing shadows JUDGE-3 photographed are a **direct
  consequence of the embedding defect** (a body sunk into or lying flat on the
  terrain casts a negligible shadow onto ground it already occupies), not a
  second, independent lighting bug. I find this reasoning sound and did not
  find a hole in it, but it is unverified by a fresh render: **nobody has
  re-shot Creek Hollow since T1-GROUND-3 landed** to confirm the flat/sunk
  cases are gone and the shadows now read.
- **The guardian's own den got a real, specific fix** — `T1-LIGHT` found every
  light in `burrow_warrens.gd` was `shadow_enabled = false` by design (a
  shadowless cave wash), so nothing standing in the room could ever cast a
  shadow at any energy; it added an opt-in `shadow: true` key on the
  guardian's own key light. I opened
  `ralph/reports/T1-LIGHT/shots/guardian_den/guardian-den-AFTER-round2.png`
  myself: the guardian now shows real shell-plate texture, a warm-lit
  background, and a visible darker patch at its feet consistent with a
  contact shadow — a genuine improvement over the flat-black read in the
  pre-fix frame. (This frame is also cited under B6, since it is the same
  fix.)
- **Open water is still a non-demonstration.** JUDGE-3 §2c: a creature sits
  entirely above the water plane with no waterline, no partial submersion, no
  ripple, no reflection — "a sticker on an opaque plane." No handover reviewed
  reports touching this.
- **Two of six Creek Hollow habitat capture stands still fail as capture,
  independent of build state**: one is shot from inside a tree trunk (a black
  frame), two photograph no creature at all. This is a capture-harness gap
  layered on top of whatever the ground truth is — it means "Creek Hollow
  looks fine" cannot currently be verified end-to-end even where the game
  itself might be fine.
- **A fresh, out-of-context blind pass run this session** (see B1's box for
  the full method) independently flagged `far_water_edge-CROP-embedded.png`
  without being told anything about the embedding defect: "the mid-distance
  hills are flat, near-white, and untextured, reading as missing terrain/
  placeholder LOD rather than grassland; it breaks the shot outright." That
  is a terrain-LOD complaint layered on top of JUDGE-3's original
  creature-embedding one, on the exact same frame, from a viewer who did not
  know the frame existed to demonstrate anything about creatures — worth
  carrying forward since it means this stand has two independent, unrelated
  problems, not one.

**Closing cost:** re-shooting Creek Hollow's six stands with the current build
is the single highest-value next step — it would either close the "flat/sunk"
half of this item or prove T1-GROUND-3's fix incomplete, and the tooling
already exists (`tools/_probe_creek_hollow_habitat.gd`). That is a capture
round, not new code. Open water depth/contact is a real feature gap (surface
interaction on water — displacement, waterline shader response to a body) and
is a genuine content/code task, not a config tweak. The two broken capture
stands are a tooling fix (fix the vantage-finder to not place the camera
inside geometry) — cheap, and this project's own conventions class it as
fair game for an audit lane to fix (the instrument, not the subject) — but I
have not fixed it, per this lane's own no-game-code, minimal-footprint
mandate; flagging it as a one-line vantage adjustment for whoever next uses
that tool.

## B6 — Silhouette reads at gameplay distance (the guardian)

**Verdict: OPEN, confirmed by a fresh blind pass run this session.** Real,
measured improvement has landed since the defect was named (see the
`T1-LIGHT` luminance numbers below), but a fresh, out-of-context judge look
at the current post-fix frame still calls the guardian unreadable — see the
box at the end of this section.

JUDGE-3 §3 found the guardian's backlight fix did not survive to real
viewing distance: its BEFORE/AFTER evidence pair was shot from different
camera angles (invalid as a controlled comparison), and even judged on its
own, `guardian-den-0830-full.png` — the frame shot from where a player
actually stands in the den — shows "a near-black lump occupying about 8% of
frame width," with the lit doorway gone and no contact shadow. I opened this
exact frame myself: it is accurate. The guardian is a nearly featureless dark
mass; almost no plate/shell detail resolves at that size and darkness.

`T1-LIGHT` subsequently found the room's actual root cause — every light in
`burrow_warrens.gd` was `shadow_enabled = false` by design, so no light in the
room could ever produce a contact shadow at any energy — and fixed it with an
opt-in `shadow: true` on the guardian's own key light, plus raised backlight/

## Addendum — the grass-separation re-measurement

Ran `tools/_probe_grass_separation.gd` against the current build (same
instrument and camera stand `species.json`'s own `_comment_field_rim_0828`
describes) — real world boot (`meadows_playground.tscn`, 315,232 grass tufts
bound, 382,817 scattered props, confirmed by the tool's own boot log), one
fixed camera at throwing range, the same four A/B/C/D variants the original
2026-08-28 measurement used (height 0.78/0.96 × rim off/0.22 — the probe
script hardcodes these two test heights rather than reading the species
table's live value, so this run does not test the shipped height of 1.00
directly; **the closest proxy is variant D, 0.96m + rim, one size step below
what ships**). All four frames are real in-world captures — I opened each
one and confirm real individually-rendered grass blades, the real HUD
(health/food bars, quest toast, hotbar), and the real fence/trees/rocks of
the corridor behind the field; the creature (the current
`bramblebun_redesign` mesh, since the probe does not override `model`, only
`height`/`field_rim`) is visible as antlered ears above the grass line in
every frame at roughly the same screen position, consistent with a fixed
camera and a small height delta between variants.

Frames: `ralph/reports/audit/grass_separation_verify/grass-{A-0.78-norim,
B-0.96-norim,C-0.78-rim,D-0.96-rim}.png`.

**The probe itself does not compute a contrast number** — the 2026-08-28
figure in `species.json`'s own comment was measured by whatever ad hoc
script or process that lane used, uncommitted, so this report cannot
reproduce its exact method. Instead I measured directly: Rec. 709 luma
(the same weighting `tools/frame_stats.py` uses elsewhere in this repo,
`0.2126/0.7152/0.0722`), one fixed creature-region crop and one fixed
grass-region crop (same pixel box across all four frames, since the camera
stand is identical), computed with `PIL`/`numpy`. I checked the crop
selection against the actual pixels before trusting it (saved and viewed
both crops myself) and cross-checked with two different grass-reference
boxes to make sure the result wasn't an artefact of the box choice:

| variant | creature luma | grass luma (box 1) | ratio | grass luma (box 2, HUD-clear) | ratio |
|---|---|---|---|---|---|
| A — 0.78m, no rim | 0.485 | 0.464 | **1.046** | 0.481 | **1.008** |
| B — 0.96m, no rim | 0.472 | 0.463 | **1.020** | 0.480 | **1.017** |
| C — 0.78m, rim 0.22 | 0.486 | 0.464 | **1.046** | 0.481 | **1.009** |
| D — 0.96m, rim 0.22 (closest to shipped) | 0.474 | 0.465 | **1.019** | 0.482 | **1.017** |

Both reference-box choices land in the same range and agree on the
direction: **every ratio here is at or below the pre-redesign figures
recorded in `species.json`** (1.15/1.08 without rim, 1.14/1.06 with rim, at
the same two heights). The redesigned mesh — taller, described by its own
lane as "heavy... with oversized ears," swapped in specifically to answer
the owner's "creatures need to stand out in the grass" directive — **is not
more separated from the grass field by luminance than the mesh it
replaced, and by this measurement is marginally less separated.** A ratio
this close to 1.0 is exactly the value this repo's own `vegetation.json`
comment names as the blind critic's own definition of invisible.

**Honest limits of this specific measurement**, stated plainly because it is
new evidence produced by this audit rather than inherited: the crop boxes
are hand-picked from looking at one frame (`D`), not derived from an actual
segmentation of the creature's silhouette, so this is a directionally
reliable but not pixel-precise number — good enough to say "not improved,
possibly worse," not good enough to replace a proper repeat of the original
lane's own methodology at the actual shipped height (1.00m, which this
probe does not test without a source change). Closing this precisely needs
either recovering/rewriting the original measurement script to accept the
live species height, or a small one-off script like the one used here
pointed at a height-1.00 render specifically.
