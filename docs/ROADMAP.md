# Roadmap — sequenced plan to a complete release

## 1. Basis and estimate

The baseline is b8eda885, not an empty project: four chapter runtimes, extensive world scripts, combat/care/build/traversal/network/save systems and large authored catalogues already exist. FINDINGS records full archive recovery and census. Most remaining work is integration, depth, asset quality and proof. Source counts are not a productivity estimate.

Assume one owner available25focused hours/week, senior design/integration and bounded lower-tier agent labor, one shared render/import machine, existing asset rights still needing audit, and no new game engine/renderer. This is a **planning estimate** with roughly±40% uncertainty before the expedition gate. Agents accelerate isolated code/data/test work; they do not replace owner taste, hardware testing, new art references, player recruitment or commissioning.

Bottom-up owner/integration effort: **780–1,180hours**, plus external art/audio labor. At25h/week this is31–47working weeks. Allow external delivery/review/illness and integration slack: **36–52calendar weeks** if gates pass. At10owner hours/week, expect18–28months. An aspirational visual bar without approved references/vendor capacity makes the finish date unbounded; no agent-throughput claim removes that dependency.

External-production planning envelope **US$15k–35k**, including prioritized creature/hero asset work, final music/audio and promotional assets, is an estimate to solicit quotes against, not spending authorization or assurance every mesh can be replaced. Full bespoke roster replacement would require a separate scope and budget. PRODUCT's unit economics is only an illustrative scenario.

## 3. Parallel work that is safe

The former four co-equal lanes—combat depth, Meadows look, Cloudreach look, density—are replaced. Combat/camera/scale, recovery/economy and content payoffs depend on each other. Their contract is settled before parallel implementation. Cloudreach look cannot certify flight readability before the route/camera works.

After shared contracts are stable, parallel bounded work may include:

- Asset provenance/reference triage and commissioned subject work while P1 mechanics are built. Named authorizations only; no blanket generation. First hero subjects are selected by ordinary gameplay importance and blind defect evidence, not model novelty.
- Audio cue inventory/state adapters and composer delivery after chapter/state requirements are frozen. AUDIO's22deliverables plus creature/interaction cues require external production time; synthesized placeholders keep integration playable meanwhile.
- Independent region rewards/dialogue/encounter composition after shared XP, party, transaction and presentation rules are fixed.
- Pure logic tests/fixture audits while one process imports/renders. Separate full-world smokes if memory contention risks invalid results.
- Store research/copy/provenance preparation; screenshots/trailer only after representative gameplay/visual gates.

No two agents concurrently change `game_state`, combat manager, common HUD/input, save schema, shared vegetation or authority code without explicit ownership/serialization. Agent briefs contain outcome, exact owned paths, dependencies, acceptance, out-of-scope and stop condition. A new framework is not automatically needed to add six authored detours.

## 4. Migration and integration order

1. Declare data schema/field defaults, ownership and receipts for injury, per-creature bond visit credit, L4 skill, cooldowns and ending flags before consumers. Preserve earned nodes and stable IDs.
2. Implement deterministic formulas and host validation; then local/remote gameplay; then UI/audio; then persisted old-save migration and failure/reconnect tests. Never ship a solo-only feature expecting a network pass later.
3. Introduce skill/poise/camera and fight profiles before rewriting the chapter enemy roster. Keep type multipliers initially unchanged; measure combined effect with existing TM powers/IVs/Best perks.
4. Validate supplies and recoverability with injury before increasing encounter density. Add lures and durable rewards before optional map counters/pins.
5. Verify starter traversal promises, chapter gates and shared realm state before final chapter route polish. Late-stage asset swaps must repeat scale/framing/landing checks.
6. Build ending once chapter/world transaction contracts are stable; completion cannot be a final-week credits-only task.

## 5. Risk register and concrete responses

| Risk | Early signal | Response |
|---|---|---|
| Five-owned model removes the motivation to catch/explore | Players settle after tutorial and ignore useful detours. | Improve role/skill/reward differentiation; retest P1. If still weak, explicitly reconsider product/hard rule with owner; never add a hidden box. |
| Creature art cannot sell the team | Blind reviewers repeatedly cite silhouette/anatomy/rig, not lighting. | Obtain owner reference/production decision for priority subjects; keep bar open. Stop tint churn. |
| Runtime exists but full route fails | Seeded smokes pass while ordinary gate, prompt or supply path fails. | Replay from last legitimately earned checkpoint; repair transaction/input/route cause; do not make harness bypass it. |
| Co-op corrupts progression | Duplicate claim, divergent realm/reward or abandoned body state. | Block feature completion, fix authority/receipts/migrations before more content. |
| Hardware misses frame budget | High P99/hitches or separated-realm host load. | Profile source hotspot, visibility/batching/residency; quality settings within art contract. No renderer switch without new device evidence. |
| Content cannot fill time well | Mandatory low-level farm or long backtracking dominates. | Raise meaningful rewards/reduce duplicate errands, improve loops; never add artificial XP grind. |
| External assets delay finish | Missing references/rights/rig delivery by P2. | Reforecast schedule and apply cosmetic scope cuts; do not claim BarB closes with stand-ins. |

## 6. Cut lines

Carry PRODUCT's exact order: fishing/survey/camp checklists and decorative extras first; then activities above six/chapter and duplicate elites; then mechanical trait perks/bespoke vocal variants; then decorative build expansion/cosmetics/postgame/localization; then promotion/date. Preserve required gameplay feedback and chapter palettes even if music production uses shared thematic arrangements.

Never silently cut four chapters, ending, five-owned identity, piloted combat depth, essential traversal/care,1–4co-op authority, save reliability or device readability. If minimum fails affordability, delay or stop and present a new product decision. Meadows can be a free validated demo; it is not the promised minimum paid game.

## 7. Reporting and release discipline

STATE holds phase, blockers, actual versus estimate and next bounded work; evidence stays in existing lane paths. No new dated goals/handoffs or per-session planning docs. Every implementation PR states built versus accepted and affected acceptance IDs. For docs-only PRs, do not imply engine tests ran. For code, verify actual CI jobs and package timestamp before asking the owner to play. One candidate build identity follows the evidence all the way to store claims.
