# R9.2 — Scope final controller UI readability on ROG Ally

## Goal
Turn the placeholder **"Controller UI readability on Ally"** into a current-build usability audit and a small actionable polish queue. This is not a license to redesign every screen.

## First rule: verify dedicated work first
Several concrete UI problems already have owned prompts:
- RG3 permanent compact exploration control legend;
- RG6 full controller/menu-input audit;
- RG14 build-placement control strip;
- RG15 minimap/full-map navigation;
- EV9 title/HUD mount points;
- TEST2 controller-event/collision regressions.

Inspect what actually landed. Do not re-open an old issue because the board header is broad.

## Target hardware / conditions
Audit at the project's actual 1920x1080 authoring target on a 7-inch ROG Ally-equivalent view, controller only. Include normal viewing distance, not desktop-window magnification.

## Surfaces to sample
At minimum:
- title/save-select;
- exploration HUD and permanent control legend;
- context prompts/hotbar/objective/minimap;
- Satchel;
- Creatures, including nickname/condition/readiness UI if RG19 landed;
- Map/full map;
- Quests;
- Build menu and armed placement strip;
- Save;
- Settings/Controls;
- dialogue/name prompt;
- combat/catch UI;
- tournament UI if present.

## Evaluate
For each surface record only concrete issues in:
- font size/readability at handheld distance;
- contrast against changing world backgrounds;
- focus visibility/current selection;
- action glyph-label consistency with live InputMap;
- clipping/truncation/wrapping;
- overlapping dynamic panels;
- excessive density requiring desktop-like reading;
- safe margins and important information hierarchy;
- ability to complete every action with controller alone.

Do not confuse aesthetic preference with a usability failure.

## Deliverable
Create a prioritized set of focused fixes. Every proposed item needs:
- screen + reproduction;
- screenshot/capture evidence;
- exact defect (e.g. 16px text unreadable, focus border indistinguishable, label clips at 1920x1080);
- current component/theme seam (`UITokens`, screen script, glyph helper, container);
- acceptance condition;
- whether one shared-token fix resolves multiple screens.

Prefer systemic token/layout fixes when the same defect appears across screens; do not individually tune ten labels that all use the same bad token.

## Controller contract
Any visible action label/glyph must match what pressing that control actually does. Use the existing dynamic input glyph system where available. Verify focus navigation with real joypad events and both d-pad and stick where current UI promises both.

## Visual review
Use screenshots at native 1920x1080 and, when judging handheld legibility, inspect at realistic physical/display scale. Follow visual-judge process for visual-affecting fixes, but usability evidence outranks decorative score.

## Preserve
- existing Palworld-inspired HUD hierarchy;
- controller-first navigation;
- current theme/UITokens unless a systemic token is proven deficient;
- no broad rebranding during polish;
- game world visibility during exploration/combat.

## Acceptance criteria
1. All major player-facing screens are sampled on current main with controller-only use.
2. Previously fixed RG3/RG6/RG14/RG15 issues are only reopened if reproduced.
3. Every remaining issue has concrete screenshot/reproduction evidence and an acceptance criterion.
4. Shared defects are grouped under shared fixes.
5. All critical text/actions are readable and operable at Ally size.
6. If no material issue remains in a screen, it is recorded as pass rather than given cosmetic work.

## Definition of done
R9.2 produces and, where small enough, resolves a finite evidence-backed list of **actual handheld readability/controller usability gaps**, replacing the vague placeholder with a clear exit-quality bar.
