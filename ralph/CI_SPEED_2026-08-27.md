# CI speed — 2026-08-27, measured

Everything here was measured in a container with Godot 4.7-stable against a
fresh clone of `main` at `f082bdf6`, not inferred. It corrects two things in
`HANDOVER_2026-08-26_COORDINATOR_2.md` §6.

## Correction 1 — the re-import hypothesis is dead

§6 item 1 proposed that `actions/checkout` stamps fresh mtimes on the imported
assets, Godot judges them stale, and re-imports. It said to test that before
changing anything. Tested:

| run | condition | seconds |
|---|---|---|
| A | cold, no `.godot` | 533 |
| B | immediately again, nothing touched | 5 |
| C | **all 12,977 tracked files touched to now**, `.godot` kept | **11** |

Godot 4.7 validates by content, not mtime. Re-stamping every file in the repo
costs 11 seconds, not 533. **Do not spend more time on mtimes.**

## What the import time actually was

`ralph/` and `shots/` carried no `.gdignore`, so Godot imported the
visual-judge output — 381 report PNGs and 161 survey files — as game textures
on every job. The largest single entry in the import cache was
`ralph/reports/gate-f-run-20260825T201354Z/X07/_sheet.png`, a contact sheet.

| | cold import | `.godot` |
|---|---|---|
| before | 533 s | 980 MB |
| after `.gdignore` | 218 s | 484 MB |

Over half of every job's import cost, and half the ~1 GB cache each job
restores, was the game importing screenshots of itself.

`contact_sheet.gd` is unaffected: it reads with `Image.load_from_file` and
`DirAccess`, which bypass the import system. Re-sheeting X07's 46 frames under
the change produces its sheet normally.

## Correction 2 — the repo-size weight is not `data/scatter`

§6 named `data/scatter/**/*.bin` as the honest fix. Measured against the
tracked tip, all of `data/` is 50.1 MB and `data/scatter` is 27 MB — about 1%.
The weight is elsewhere:

| tree | tracked | read by any CI job? |
|---|---|---|
| `assets/` | 796.7 MB | yes |
| `ralph/` | 736.7 MB | no |
| `assets_raw/` | 350.0 MB | no — `.gitignore` says never-commit |
| `docs/` | 69.0 MB | no |
| `data/` | 50.1 MB | yes |
| `shots/` | 47.0 MB | no |

1.20 GB of 2.08 GB is unread. Excluding those four trees via blob:none +
sparse-checkout takes a verify checkout to 895 MB, verified on a real clone:
imports clean in 224 s, smoke and unit shard both green.

**Still an owner decision, and not done here:** `ralph/reports`' 381 PNGs and
`assets_raw/` are in git history, so `.git` stays 1.8 GB and every full clone
still pays for them. Sparse-checkout avoids the cost in CI without touching
history. Removing or LFS-ing them is the only thing that shrinks the clone.

## Job structure

16 jobs carried `if: false`, superseded by shards but never deleted — 1342
lines that ran nothing and showed as 16 skipped entries every run. Deleted.

The five remaining shards ran their smokes serially, so each cost the sum of
its smokes and sat near its 22-minute ceiling. Two of one shard's seven smokes
measured 248 s and 121 s here. All five are now per-smoke matrices, so a job
costs its longest single smoke. Coverage is identical: 35 distinct smokes
before and after, none lost.

`party_count_after_catches` keeps `retries: 1` on purpose. It is the
known-intermittent catch-3 engage defect and a retry would green it and hide
the cause — the same reason `stick_navigator` is withheld from it. Its own leg
means its flake no longer fails six unrelated owner regressions with it.

## Not measurable from this container

Live legs go 26 -> 51. They contend for runners, and the handover measures
checkouts degrading to 7-12 minutes under load. The sparse-checkout change is
the paired mitigation. Whether the net is positive needs one observed run —
this session had no GitHub Actions access and could not read one.

The remaining floor is unchanged: `test_scatter_rules.gd` is ~11 minutes in a
single process and no split touches it. Going below that is an owner decision
about the test, not plumbing.
