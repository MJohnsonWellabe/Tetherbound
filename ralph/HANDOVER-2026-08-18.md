## 5. Process notes, earned the hard way today

- **Bundle three or more green branches onto one `ralph/integrate-N`.** Still
  correct, but **not for the reason `COORDINATED_RUN.md` gives.** That manual
  says CI allows ~5 concurrent jobs per run. Measured on run 1456 (2026-08-18):
  **all 18 jobs started within 54 seconds of each other.** There is no 5-slot
  per-run cap. The cap is an account-wide pool that only bites when several
  runs are in flight together — which is a situation the coordinator creates,
  by pushing three branches at once, not a property of one run. Bundle because
  fewer runs means less contention for that shared pool and fewer merge-ordering
  hazards; do not bundle because you think adding a job is expensive. It is not.

- **Job timings, measured on the same run, so the next person does not have to
  guess where the time goes:** `changes` 50 s; the thirteen other verify jobs
  **181–264 s**; `verify-unit-tests` **12+ minutes**. It was not *a* long pole,
  it was the *only* one — every other job finished by ~5 minutes and the run
  then sat idle waiting. That is what made the shard split worth doing: it cut
  the run from ~13 minutes to roughly 7, on top of buying the timeout margin.

- **A `timeout-minutes` kill is reported as CANCELLED, not failed.** This is the
  single most misleading thing in this repo's CI. It reads as though a human
  aborted the build, and `ralph-merge` refuses a cancelled run permanently, so
  a few seconds over the line costs the whole run again. If a run says
  "cancelled" and nobody cancelled it, check the run's elapsed time against the
  slowest job's `timeout-minutes` before believing anything else.

- **The unit suite is sharded** (`--shard=I/N`, round-robin, 2 shards as of
  2026-08-18). Running `tests/run_tests.gd` with no flag still runs everything,
  so local invocations are unchanged. If it clips again, add a third shard —
  the runner already takes any N.
- **Docs-only paths** (`ralph/`, `docs/`, `site/`, `.claude/`, any `.md`) skip
  every verify job and finish in ~1 min; code paths take ~8.

  **THE RULE: never push a docs-only branch while a code bundle is in flight.
  Commit bookkeeping ONTO the integrate branch instead, so it shares that
  bundle's single CI run and lands with it.**

  This is written as a rule rather than a lesson because prose did not work.
  This coordinator wrote "do not push bookkeeping while a code bundle is in
  flight" into this very file, pushed that sentence as a docs-only branch while
  `integrate-11` was mid-run, and the ~1 min docs run beat the ~8 min code run
  to `main`. `ralph-merge` fast-forwarded `main` to the docs commit, which put
  `integrate-11` *behind* `main`, where `ralph-merge` refuses it permanently.
  Recovery cost a full extra CI run. It had already happened once earlier the
  same evening. A warning you have to remember to apply is not a control; a
  rule about where the commit goes is.
- **`ralph-merge` cannot fast-forward a branch behind `main`.** Merge `main`
  INTO the branch. Never rebase anything carrying merge history.
- **Archive a lane in the same pass that lands its work.** This was missed for
  four lanes in one evening until the owner asked why so many sessions were
  open. Land → close the backlog item → archive. The third step is the one that
  gets dropped.
- **The `export` job only runs on `main` or `workflow_dispatch`.** It is skipped
  on branch push, which is why export breakage only ever appears on the merge
  path.
