# Lane W24-LANDING — the one lane whose only job is getting finished work onto `main`

Branch: `ralph/LAND-0904` (a consolidation branch you re-create from `origin/main` for each landing cycle; name later cycles `ralph/LAND-0904-2`, `-3`, …). Model tier: integration judgement.

**Why.** Twenty-four lanes were launched on 2026-09-04 (ledger: `ralph/briefs/0904/LANES.md`, briefs beside it, each with an exclusive file-ownership list). Ten are active, fourteen are paused with partial pushes. Nothing gets to `main` unless someone verifies it, consolidates it, runs CI, and merges. That is you, continuously, until every lane is landed. You never write feature code; you land other lanes' code.

**What "done" means for a lane.** Its branch `origin/ralph/<LANE>-0904` carries `ralph/reports/<LANE>-0904/REPORT.md` with a commit hash, AND the report's test claims reproduce on the branch (you run the named tests yourself, Godot installed per COMMON.md), AND the diff stays inside the brief's ownership list (`git diff --stat origin/main...origin/<branch>` against the brief). A lane branch without a report is not done: leave it alone. A lane whose report claims tests it did not run is not done: leave it and record why in your report.

**Landing cycle (repeat every time you are woken, and after each merge):**
1. `git fetch origin --prune`. List `origin/ralph/W*-0904` branches; for each, check for the report file and the ahead count.
2. **First, `main` itself.** `main` is red on `verify-unit-tests (3)` (`test_item_icons.gd`, six missing candy/mushroom icons); lane W00-ICONS (`ralph/W00-ICONS-0904`) fixes it. Land W00 ALONE first, the moment its report exists: PR → wait for the PR's CI run to complete (a run under five minutes verified nothing; check code jobs executed) → merge. Do not batch anything with it.
3. Then batch the other done lanes 3–5 at a time into a fresh `ralph/LAND-0904-n` from `origin/main`: `git merge --no-ff origin/ralph/<LANE>-0904` one by one, resolving conflicts by reading both lanes' briefs (contended files: `scripts/combat/combat_manager.gd` — W09 VFX hook, W10 `_flee_pressed()`, W12 result-beat hook, W13 crediting line; `scripts/world/playground_world.gd` — W17 loader hook; `scripts/creatures/creature_body.gd`; `data/dialogue/stronghold.json` — W06 owns text+portraits there, W04 owns every other dialogue file). Never drop either side's behaviour; if two lanes changed the same logic and you cannot keep both, stop that lane out of the batch and report it. **Bake rule:** if a batch includes a lane that touched `data/config/vegetation.json` or any band `vegetation.json` (only W05 may) together with any other bake-input change, re-run the scatter bake on the merged tree before pushing (`scripts/world/bake_playground_scatter.gd`; the freshness test `test_scatter_perf_budget.gd::test_playground_bake_is_committed_and_fresh` must pass on the MERGED tree, not just on each branch).
4. On the merged tree run: `godot --headless --path . --import` (grep the log for `SCRIPT ERROR|Parse Error`), `tests/smoke_playground.gd` (grep `^ERROR:`, read the set), plus every unit/smoke each landed lane's report names (`-- --only=<file>` per file). Fix nothing in lane code except trivial merge fallout; anything else goes back as "not landed, reason".
5. Push the branch (CI runs on `ralph/**`), open a pull request to `main` titled `Land <lanes>` whose body lists each lane with its report path and what a player gets, using the GitHub MCP tools (`mcp__github__create_pull_request`, `pull_request_read` with `get_check_runs`/`get_status`, `merge_pull_request`). Wait for CI to COMPLETE — poll with the GitHub tools, never `sleep` loops longer than a few minutes; read every job's conclusion, not the top line; `RETRIES` rescuing a 0-for-1 is a finding you record. Merge only on a fully green run whose code jobs executed. Then `git merge-base --is-ancestor <sha> origin/main` to confirm the landing. If the GitHub tools are unavailable in your session, push the consolidated branch, write the PR body into your report, and say so plainly — the coordinator will open and merge it.
6. After each merge, note it in `ralph/briefs/0904/LANES.md` (on your landing branch is fine; the coordinator mirrors it) and in `docs/CURRENT_STATE.md` §1 "Git truth" (one line per landing: PR number, lanes, SHA). Keep `ralph/reports/W24-LANDING-0904/REPORT.md` current: per lane — landed (PR, SHA) / not landed (exact reason) / not yet done.

**Owns:** the landing branches, `ralph/briefs/0904/LANES.md`, `docs/CURRENT_STATE.md` §1, `ralph/reports/W24-LANDING-0904/`, merge-conflict resolutions, a re-bake on a merged tree. Nothing else. Never rewrite history on a lane branch, never force-push, never push to `main` directly, never merge a red or incomplete run, never land a lane without its report.
