Why this reads top-to-bottom, and not by lane

Order is priority, and it's load-bearing. BACKLOG.md's own preamble says "ordered, work top-down" — every firing's first move is to take the topmost unblocked item. The negative-numbered phases below (-1 through -0.5) exist so owner-driven urgent work can be spliced ahead of the plan without renumbering anything, so this page keeps that exact order rather than sorting by date or topic.

"Lane" isn't a subject — it's a rotation slot. There are three lanes (a keyed cron Routine, Lane B, Lane C); B and C run the same prompt with one word changed, and each just claims whatever unclaimed item is topmost. Grouping this ledger by lane would cluster unrelated work and split related work, essentially at random — so it isn't offered as a view here.

Closed items are collapsed to a single count per phase. A few carry real context an open -remainder item still depends on to make sense — those are kept, under a load-bearing expander, right where they're needed.
