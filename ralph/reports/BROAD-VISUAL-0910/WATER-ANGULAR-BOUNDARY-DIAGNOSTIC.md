# Water angular boundary diagnostic

The remaining Gull Rest boundary changes slope in screen space and keeps the
same geometry by day and night. That does not match the one straight projected
diagonal available from the production two-triangle water plane. The production
water shader also samples terrain height and computes depth, colour, and alpha
per fragment. Its mounted visual contract overrides the shader defaults with
`alpha_deep = 0.9` and `alpha_shallow = 0.45`, leaving the submerged scene visible
through both ranges.

Godot's Compatibility renderer is not known here to compute distance fog once
per water vertex. In the current upstream GLES3 scene shader,
`fog_process(vec3 vertex)` executes in the fragment section and evaluates
`length(vertex)` for depth or exponential fog. The source is `master`, so the
native diagnostic remains the authority for the project's installed 4.7 build:
<https://github.com/godotengine/godot/blob/master/drivers/gles3/shaders/scene.glsl>.

`tools/probe_water_angular_boundary.gd` captures the ordinary Gull Rest daytime
baseline and then four isolated controls at the same physical camera and pinned
clock. It disables world processing only between these captures while leaving
the capture pipeline alive. Each variant restores the exact original mesh and
material identities before the next variant:

1. 63-by-63 subdivision with the original material;
2. `alpha_deep = 1.0` with the original two-triangle mesh;
3. `fog_disabled` added to a duplicate shader, with all material bindings kept;
4. the shader's exact current height-sampling block replaced by constant
   `ground = height_min`, leaving shallow, foam, wave, and texture bindings intact.

Interpretation: a change only under subdivision implicates interpolation; a
change only under opaque deep water implicates visible submerged terrain; a
change only with fog disabled implicates Compatibility transparent fog. If only
constant depth removes it, the angular colour is generated by the baked height
field rather than by the rendered seabed. No production resource is changed.

Run through the normal native capture wrapper with:

```text
--script res://tools/probe_water_angular_boundary.gd -- --output=res://shots/catalogue/water/broad-angular-boundary-diagnostic01
```

The receipt must show nine frames, one replacement for each shader edit, mounted
alpha readbacks of 0.9/0.45, matching texture instance IDs, restoration after
every control, and final restoration of world process mode and production mesh
and material identities.

## Actual result

`water-angular-boundary-diagnostic-first` completed cleanly at
07:26:18–07:27:56 UTC: nine frames, exit 0, no engine errors. Shader replacements
each occurred once; all controls restored their original objects and alpha
0.9/0.45. Direct inspection found that only deep alpha 1.0 removed the angular
boundary. Subdivision, disabled fog and constant sampled depth retained it.
This implicates the visible submerged scene contribution; it does not support
water-plane tessellation, fog interpolation or the depth-colour lookup as the
cause. The resulting production candidate is recorded separately in
`WATER-DEEP-OPACITY01-CANDIDATE.md` and still requires visual acceptance.
