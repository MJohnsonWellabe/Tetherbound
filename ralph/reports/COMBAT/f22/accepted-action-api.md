## Concrete producer

`EncounterHost._strike_authority[encounter][peer].accepted_actions[action_id]` is the only action registry. It retains the original equipped move, mastery rank, stable character, owned UID, body generation, host action, request token, resource start candidate, real launch frame, first arrival decision and published receipt/result. Deep original values are read-only; returned projections are copies. Its 4096-entry configured bound refuses new actions and never evicts replay history. Round change, cancellation and close preserve originals; forget remains gated by pending action publication and pending actor vitals. Stable-owner retention uses Foundation's existing leave/rejoin state move.

The minimal client start request is exactly `{kind, encounter_id, creature_uid, slot, move_id, start_token}`. The opaque one-use token comes from the current host action view. This addition is necessary because the earlier four-field F23 request cannot distinguish a delayed duplicate from a fresh tap after cooldown. No client action ID, generation, position, tier, mastery rank, power, HP, meter or resource balance is accepted.

Start freezes F23 once and commits current UID resources once. Release retains actual host body identity, launch point/facing and finite arrival deadline. Arrival revalidates the same alive actor generation and current opponent identity/generation/HP, then stages F23 damage, utility, mastery and ultimate gain. A distinct earlier action may arrive after a later action without a high-water credit shortcut. Duplicate arrivals return the original plan/result. Switch, faint or lifecycle cancellation invalidates unsettled flight; a staged writer decision is preserved until reconciliation.

F24 `stage_landed` consumes the SAME F23 accepted receipt and actual clamped HP debit. `meter_credited` and `command_meter_credited` belong to that receipt. There is no meter grant from the latest-strike debug cache, VFX, `hit_landed` or a separate receipt ledger. F24 admission and command execution are still separate required consumers; this proposal does not implement item throw, Rally, Snare or the outgoing/incoming combo writer.

Wind, energy, ultimate, slot cooldowns and movement commitment remain on each of the at most five canonical actor rows. Existing participant Wind is the active-row projection. Binding another UID saves/restores that projection without transferring resources. The pending-outcome fence blocks HP/resource/actor/phase/round/teardown mutation until original publication and body delivery complete. Exact previous HP ACKs may change `settled_revision` without invalidating the economic/body CAS.

Utility state uses the stable encounter lifetime at generation 0, distinct from the strict frozen actor body generation. It seeds `UtilityEffects.empty_state(encounter, 0)` once and keeps earned receipts/statuses across own switches. The ignored F23 helper delta passes this explicit lifetime to utility staging while retaining all actor UID/body checks. Miss, out-of-range, immunity and full-health utility arrivals settle once without mastery or meter and cannot be retried into a hit. Actual movement/status/field effects still need ROOT's shared body consumers.

The Director proposal adds dispatch, host-clock release/arrival scheduling, original decision retries, trusted body mirroring and the F27 killing-hit capture before terminal publication. Published decisions stay pending until the same body projection/capture is delivered. F25 receives the full frozen row, same action binding, finite host schedule and both actual body-ground origins; confirmed contact precedes body/HUD HP projection. Actual impact audio classification/playback and guest/reconnect projection transport remain ROOT consumers.

## Still-unconnected Foundation Session facade

These methods are **required contracts, not implemented APIs**. Missing methods refuse the producer. A dictionary claiming `ready`, `durable`, `saved` or `acknowledged` proves no authority.

`Session._host_move_action_context(actual_director: Node, encounter_id: String, peer_id: int, creature_uid: String) -> Dictionary` must authenticate the actual current Game Session, actual Director/EncounterHost/body lifetime, prepared-world namespace and stable admitted CharacterAuthority row. It must refuse an unadmitted/aliased UID, stale generation, active pending registry/portal/vitals/character decision, unsupported remote owner, changed snapshot or unready durable pipeline. Its canonical response contains `ready`, `character_id`, full `owned_row`, `completed_tiers`, actual derived `combat_stats.attack`, actual `wind_profile`, optional `quick_energy_multiplier`, and a `move_delivery_seconds` dictionary for quick/charged/utility/ultimate. Each delivery value must be finite 0–3 seconds from authored host move data, frozen at start; no presentation estimate or packet chooses arrival time. ROOT must supply/compose those authored delivery definitions before activation.

`Session._commit_host_move_action_outcome(actual_director: Node, original_bundle: Dictionary) -> Dictionary` must re-read the same retained Host original and stable admitted row, then use the **same CharacterAuthority pending journal** to stage mastery and any source heal together. It must retain the first plan, original identity/rank/roll/HP debit, baseline and pending journal through failed bool save, disconnect, owner ACK refusal, crash/reload and writer-publication retry. It must reconcile an existing durable decision before staging anything new, and prevent registry, portal, deploy, party, gear, lesson or other character decisions from overtaking it. No second action journal or writer is authorized by this proposal.

Only after the real same-journal bool world/owner writes and exact owner ACK succeed may the authenticated facade call `EncounterHost.publish_move_action_outcome(original_bundle, durable_receipt)` while the same current pending fence is held. The internal durable receipt carries `durable=true`, `saved=true`, `acknowledged=true`, original `action_id`, `character_id` and `creature_uid`; those fields are matching data, never an authorization mechanism. Host publishes actual opponent HP, self-vitals, utility, perUID resources and F24 receipt markers as one current original decision. The facade returns `{ok:true, durable:true, published:true, verdict:<same Host original result>}`. Writer failure returns pending/refusal while preserving the original bundle and balances; no local award or rollback reconstruction is allowed. The Director verifies the canonical published result before mirroring its body and capturing F27.

Pending publication must retain the actual body/current generation through disconnect and travel; if the body disappears, the original delivery fence remains held for owner reconciliation. Durable self-vitals ACK must use Foundation's existing original settlement receipt and latest revision. Canonical incoming enemy HP/effect writers, F24 commands, hosted named final-outcome contributor capture and shared visual/status consumers must honor this same fence. Those adapters remain unconnected here. An offline helper, this patch, or a future test double cannot certify that durable pipeline.
