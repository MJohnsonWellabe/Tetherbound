Bounded source findings
1. The new bool loadout_initialized is live-only and starts false. It is not a client-supplied permission, durable schema version, invented known ID, or fixture-name exception. initialize_loadout requires an actual Dictionary moves block before setting true. Existing from_species sets the real authored defaults and invokes that initializer; its source body is unchanged. Custom/no-moves definitions therefore no longer gain F23 knowledge merely by coinciding with a catalogue/learnset ID.
2. _party_to_array always preserves the original quick/charged and unrelated individual state. It emits the complete seven-field document if the marker is true OR any known moves, mastery-use dictionary, mastery-receipt dictionary, utility/ultimate string, nonzero revision or edit receipt is present. Thus clearing the live marker cannot hide populated modern state. There is no partial seven-field writer branch.
3. _array_to_party validates the whole party/carrier before clear/apply as previously. It reconstructs CreatureInstance.new(), preserving the distinction instead of invoking from_species. A valid present seven-field document sets the marker true and restores all modern values, including a legitimate all-empty document. Absent modern fields leave the marker false and preserve original equipped quick/charged strings; the next ordinary save does not invent modern knowledge/mastery/eligibility. No identity/species/stat repair or duplicate-UID remint code changed.
4. party_loadout_errors, admitted_party_errors, allowed_saved_moves, stage_saved_loadout, stage_loadout_edit and character_loadout_mirror compare exactly with the pinned original. Partial modern documents still refuse; canonical UID uniqueness, saved slot/knowledge/mastery/receipt validity, authored eligibility, typed mirror and strict admitted known-species rules are unchanged. The compare-carrier branch still rejects missing modern fields when a modern move carrier already exists. Local old-row tolerance does not become an admission fallback.
5. refresh_known_moves now returns for uninitialized rows. Initialized real authored creatures and restored modern rows still gain eligible knowledge when the existing level methods call refresh; the guard changes no level/stat arithmetic. This also prevents ordinary leveling of local legacy/custom rows from silently restamping their generation.
6. All CreatureInstance function bodies are unchanged. Only Teaching.initialize_loadout/refresh_known_moves and SaveGame._party_to_array/_array_to_party change. Snapshot, schema/version/refusal and all other save functions remain identical to the declared combat base. No v27-or-older reset/refusal behavior, test assertion, fixture, test selection or skip/quarantine is altered.

Explicit legacy gameplay/initialization gap
A known-species old v28 row with no seven-field document remains uninitialized after Continue and has an empty modern known list, even if its saved quick/charged IDs are legitimate. The only actual initialize_loadout call found is from_species; the restoration path uses new(). Existing gain_xp/gain_levels/set_level call refresh, which now returns for such rows. The current local Altar stage cannot equip a nonempty quick/charged request absent from that empty known list. The active-session Altar path explicitly refuses an encoded row without known_moves as canonical_loadout_unavailable. There is no implemented authoritative station/admission initialization transaction for these existing owned rows in this patch.
This is a disclosed future integration requirement: initialize from actual authored definitions/earned eligibility at an appropriate host-owned boundary while preserving UID, existing equipped moves, earned knowledge, mirror, personal durability and rollback. Do not mint packet identities, arbitrarily trust saved moves, reset earned records, or claim old-row F23 functionality from this codec pass. The patch's purpose is honest local absence compatibility, not a completed migration to playable modern loadouts.
