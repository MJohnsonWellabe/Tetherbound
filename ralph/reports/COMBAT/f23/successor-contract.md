# F23 bounded consumer successor

This successor preserves the original reviewed packet and producer interface.
The original39ca697f87 owned source and root-a5f16 shared patch9479e602 remain
read-only evidence. No runtime activation, engine or acceptance claim follows.

F25's exact metadata proposal matched moves SHA256
3da86de7bd8f45918ce4b9037d7f9bc1cfd0382d512de7a3a2deb0fce6987e6e.
Applying its 94 VFX blocks changes only 63 ordinary `mastery_owner: f25` tags
and 24 signature archetype aliases: boulder→stone_throw,
water_wave→tidal_wave, wind_blades→wind_blade, dark_wave→shadow_bolt,
ice_spikes→ice_shard_volley. All non-VFX move fields and all remaining visual
parameters are unchanged. IDs, equipped/signature mapping, geometry, timing,
cost, damage, utility effects and breakthrough metadata retain F23 authority.

Ordinary `effect_tier` returns unscaled tagged VFX plus frozen rank/tier;
F25 applies its authored visual tier exactly once. Signature visual growth
remains in F23 because signatures have no ordinary owner tag. The earlier
generic MoveProjectile presentation call is an integration dependency: ROOT's
real release producer must pass the full host-frozen move row and F25's trusted
current actor/action/generation plus host-clock travel duration, not only
`move.vfx`. Visual endpoints/ground anchors come from that same host action.
F35 consumes the unchanged canonical signature ID through F25. No animation
callback creates damage, meter, mastery, receipt or actor authority.

F25's prototype and F23 runtime remain OFF until this producer route is
integrated and independently proven. An owner tag alone is not integration.

F33's host preparation may add `gear_ultimate_gain_multiplier` to the SAME
frozen accepted action after F23 mastery/breakthrough composition. The host
producer copies the trusted F33 gear-config bound into
`meter_config.gear_gain_multiplier_cap`. The F33 config path is
`gear.json::limits.ultimate_gain_multiplier_cap`, currently authored as 1.52
(F33 source candidate SHA25647b65886fe6b801ed4965b8f606e24657038f6de726ad54d3eca9b290726daf9;
its independent final cut remains a dependency). Both meter fields default to one when
absent. A multiplier below one, nonnumeric/nonfinite, or above the finite cap
is refused before staging any change; overflow is also refused. This does
not load F33 config or introduce gear/meter authority in the helper.

Landed gain is the configured slot gain multiplied once by the frozen gear
factor, then capped to meter maximum on the SAME actor. Zero signature gain
stays zero. All existing actual-debit, UID/generation, original receipt and
replay fences run before enrichment. Host admission must validate that the
cap and factor came from canonical equipped gear at acceptance; a peer value
or presentation dictionary is not authority. Config-cap copying and F33
frozen-profile preparation remain producer integration dependencies.

COMBAT §3's `damage.max_bonus_product` (default1.6) caps the Hearten/Sap
encounter effect product. Nonnumeric/nonfinite/below-one caps refuse the
stage. Frozen mastery, breakthrough and canonical Charm power stay outside
this encounter cap. The host must compose any additional Rally/stagger
encounter bonuses in the same capped product, rather than multiplying them
again after the staged outcome; that wider producer composition remains OPEN.

ROOT's existing combined proof ticket must cover F33 multiplier absent/one,
canonical equipped Charm, actual positive clamped debit, same original receipt
replay, invalid type/NaN/infinity/negative/oversized factor and cap, signature
zero gain and meter saturation. This is part of the one integration batch,
not another engine run from F23. A failed stage must publish no HP, meter,
mastery or receipt mutation. F25 proof also checks ordinary visual tiers are
applied once, signatures retain their growth, and all full-row birth/context
failures produce no visual/hit authority.

F25 final source is a93815e497dfd17f0b4c985797d95ab229ac119f, draft PR517;
`f25-final-contract.json` records its exact dependency and source-contract hash.
Production ordinary birth requires BOTH finite Vector3 `source_ground` and
`target_ground`, `current_actor` including the SAME accepted action at birth,
and finite `travel_seconds` in 0..3 from the immutable host schedule. Only
positive finite optional target visual bounds may fall back to contact.

The existing accepted-action owner calls `confirm_impact` before exposing the
HP/HUD number, then resolves `MoveProjectile.impact_cue(frozen_row)` and plays
one classified contact cue from that receipt. The renderer's
`impact_audio_owner=receipt` is a presentation ownership marker, never HP or
receipt authority. Host source/target generation and alive-state checks,
cancellation and expiry still own damage. Visual arrival, timeout or node
removal cannot authorize a hit. This ordering/audio/lifecycle path remains
an unrun producer proof in the combined ROOT ticket.
