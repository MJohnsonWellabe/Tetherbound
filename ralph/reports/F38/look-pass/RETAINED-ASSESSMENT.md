## Integration audit of the final shared candidate

Root requested a separate audit of `62a862b9d6` before further art. It found two concrete integration defects and no reason to retune colour values:

1. **Authored material normals/UV2 AO:** preserving the normal texture property did not preserve its rendered contribution. Godot's [StandardMaterial detail implementation](https://github.com/godotengine/godot/blob/master/scene/resources/material.cpp) blends the base normal toward the detail normal using detail-albedo alpha. Our opaque procedural detail therefore replaced the authored normal. Also, enabling UV2 world triplanar for that detail could redirect an AO map authored on UV2. The repair adds procedural detail only when no authored detail/base-normal or UV2 AO feature is active. Toon/rim remain eligible, all authored textures/UV settings stay intact, and materials without those features retain the detail term. The regression checks feature state and UV ownership as well as resource identity.
2. **Earth-bank fragment spaces:** its inherited code treated fragment `VERTEX`/`NORMAL` as world space because `world_vertex_coords` was set. Godot's [spatial-shader contract](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/spatial_shader.html) makes that flag a vertex-stage convention; fragment inputs are view space. In the candidate arm, the bank now converts position/normal into world space for its triplanar/slope calculations, then returns the final normal to view space before the shared detail term. The OFF arm retains prior behavior for comparison. This corrects an inherited coordinate assumption within candidate scope; it is not an artistic retune or a claim the prior bank was visually accepted.

**LUT colour-space audit:** the numeric curve is a post-tonemap SDR channel mapping. The upstream [GradientTexture1D generator](https://github.com/godotengine/godot/blob/master/scene/resources/gradient_texture.cpp) writes gradient samples directly to floating-point texture pixels when `use_hdr` is true; it does not apply an sRGB-to-linear conversion there. Therefore no extra gamma conversion is inserted into the LUT. Its name refers to float storage, not HDR display acceptance. Sampling of the pinned engine's final SDR render, including existing BCS composition, remains a native witness; source curve/endpoints alone do not certify displayed colours.

**Propagation audit:** the surface watcher handles existing descendants and batches subsequently added geometry; grass/cover/stone builders install their shader material before adding children or complete synchronous `_ready` construction before the deferred flush. The village applies retints before add and builds/batches within the same synchronous placement call; generated batches have materials before add. Vegetation's `_tint_for` calls the Meadows material finisher before caching, packing Terrain3D mesh assets or later regrowth reuse. Existing runtime ShaderMaterial/MultiMesh identity handling preserves ongoing writers. No confirmed missing propagation path was found in those inspected builders; this does not cover arbitrary future material replacement on an already finished node. Keep actual placed/streamed/regrowth witnesses in native verification rather than adding a speculative global polling loop.

**Clock/weather audit:** both pinned `apply_time` and continuous `blended_config_at` feed the same environment hook after weather layering. Existing day/night and held-night boundaries are unchanged. The grade helper preserves exposure/BCS and caches one LUT/environment; the terrain uniform hook reapplies after build.
