## Explicit implementation decisions

- Only a live non-host `Game.enter_realm` starts the new drain transaction. Solo is a no-op; the existing host replacement path stays intact except an asynchronous finite interlock while an already-active client token pins its source/target. Never wait on another player's fight. Existing host state-rebuild defects remain open.
- New gates are overrides tied to a host-issued `(session epoch, mover, sequence)` token and phase. Outside an affected token, preserve existing unknown-peer/initial-join and host behavior. Do not introduce a global ready registry.
- Root approved the necessary completed-token lifetime extension: retain a receiver denial for the session epoch, departing peer and departed realm after the active transaction ends. Otherwise remote-owned admission's original default would respawn into the deleted scene. Clear only on explicit successful readiness for that realm (including rebuilt rollback), actual peer disconnect or session reset. Readiness compares the deny captured by its own transaction; stale/duplicate completion cannot clear a newer deny. Failed re-entry leaves it closed. Unrelated peers and realms retain their baseline policy.
- Root approved a second narrow lifetime extension for bodies created for the controlled mover: host-generated immutable origin metadata in authoritative trainer/creature spawn payloads. Existing non-host receivers without that target realm remain denied for those bodies after the transaction ends; no dummy target receiver is built. Later successful readiness clears only its captured matching origin generations. Host remains a receiver. Disconnect removes that receiver identity; last-live-body collection removes the origin. A later creature deployment uses its owner's still-live trainer cohort. Rollback source and abandoned destination have distinct origin keys. Untagged bodies and new peers outside the controlled transaction retain prior initial-join policy; this is not a global admission rewrite.
- Attach host-owned empty-property AdmissionSync after the existing recursive owner-authority assignment but before tree entry. For a host-owned trainer, AdmissionSync agrees with the existing realm predicate, so engine OR visibility does not widen it. For peer-owned trainer/creature state, default host admission preserves the engine's previous no-host-authoritative-sync fallback. State Sync adds only a token-scoped outbound denial.
- Register actual trainer and deployed-creature spawners and enumerate every active authored spawner in the source subtree. Unsupported nonempty kinds fail before detach; empty ItemSpawner is observed. Actual `spawned/despawned` events, parent inventory, and the host channel0 fence jointly prove drain.
- All affected sender→receiver state/body reliable0 traffic and scene-bound reliable1 traffic close before their respective fences. Body presentation is ephemeral and can be omitted only for the retiring receiver; a gated landing request completes with an explicit local refusal, and a prior request's response must be delivered or explicitly cancelled before detach.
- Director deployment/recall, encounter intents/verdicts, records, enemy-hit/catch messages, encounter-open and reward sends use narrow recipient hooks. Pending request responses cannot be silently lost. Committed trainer rewards include XP applied on the owning client, so they must have a persistent delivery route if their old director is retired; items/flags already use the persistent ledger. Preserve other participants and their authority world.
- Source correction to the review: `night_rest.attach()` mounts RPC-bearing SleepVote at `/root/Game/Session/SleepVote`, not in the retired world subtree. Its channel1 traffic survives and must remain ungated. Its local world fade references are separate from that stable RPC path.
- Source/target host shell pins cover only the active finite client transaction; no authority subtree rebuild. Commit new realm membership with destination admission closed, let the host's destination adapter become ready, then admit after the client's existing authored readiness seam. Initial/rejoin policy outside the token remains unchanged.
- Every Game await checks the captured session identity/epoch and local transition ownership before mutating a scene or compensating state. Host loss follows existing title/session-end behavior; no late coroutine can replace the title. Before-detach cancellation reopens the old receiver; after-detach rollback rebuilds and readies it before reopening admission. Save compensation failures retain their guarded recovery overlay.
