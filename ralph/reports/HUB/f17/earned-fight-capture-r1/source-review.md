Initial source findings to address before certifying a truthful fresh-fight witness:

1. Preflight requires `--through-opening`/`--no-checkpoints` but currently permits `--legacy-order-diagnostic` together with resume, dry-fixture or later-stage options. The inherited legacy path can then skip the fresh opening and eventually return a passed prefix while the manifest still says fresh title/starter/catch. Reject legacy/resume/dry/stop setup paths; keeping the canonical F49 path also retains its own refusal of those options. Do not treat an exact-looking source argument as proof that such a run was fresh.
2. Manager `is_fighting()` is true for both ACTIVE and RESOLVING (`state != INACTIVE`). Current `live_frames` can therefore be satisfied by resolving frames alone. Record actual manager state and require at least one actual ACTIVE combat sample with valid live creature references/HP. Record resolution and aftermath honestly; do not stretch combat or hold actors alive to manufacture a 30s fight. Thirty seconds may include ordinary aftermath and must be labelled that way.
3. Rows currently echo the requested preset. Verify actual `GRAPHICS.selected()` and renderer for each saved image and record those actual values, failing on drift. Native window/pixel size and initial renderer validation are useful but do not establish the later preset state.

The current timestamp is a wall-clock tick, not an ideal 100ms grid. The 100ms value schedules a next request after each capture; rendering, saving and frame load can produce wider gaps. Preserve those actual gaps and encode retained motion with those timings. A first live PNG still is useful alongside JPEG motion, but cannot substitute for the active-fight samples and full motion stream. The code shown in this initial snapshot does not yet save that PNG.
