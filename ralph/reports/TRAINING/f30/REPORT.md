## Typed integration contract

The frozen Foundation Session consumer doors are:

- `quote_altar_traits(station_key, owned_uid) -> Dictionary`
- `submit_altar_trait(station_key, intent) -> Dictionary`
- `reconcile_altar_trait(station_key, ORIGINAL_intent) -> Dictionary`
- `altar_trait_completed(station_key, action_id, result)` signal

Intent has exactly seven fields: `action_id`, `action` (`teach` or `release`),
`creature_uid`, `trait_id` (empty for essence-only release), `slot` (teach
1–3, release -1), `payment_item` (empty on release), and
`expected_character_revision`. It carries no character claim, balances,
costs, proposed roster, traits, roll or currency rewards.

Foundation must bind sender to the same admitted stable character and
current record generation, validate the actual registered Altar and reach,
recompute `Traits.stage_action` from that exact record, and prepare/commit
through the existing journal/writer. Freeze the chosen trait in the original
intent. Journal durability followed by the exact owner's boolean save and
ACK precedes success; reconnect must recover the original action against
the same stable owner. The service retains its original request on a failed
save/ACK and rejects callbacks from an old Session instance.

Host spawn registration calls `TraitSpawnHooks.prepare_host_spawn` with
actual world namespace, spawn ID/generation and host alpha/night/weather
facts. Retain that packet in the existing spawn record and announce it.
Catch admission calls `prepare_catch` with the SAME retained packet and
exact host identity before updating the existing per-UID character record.
Clients never roll or submit traits. Foundation must wire these actual
callers; the current main source lacks a sufficient spawn-identity producer.

Reuse `redesign_character.creatures[uid].rolled_traits`, `taught_traits`
(keys 1/2/3) and `breakthroughs`. Add `traits_initialized` to distinguish a
lawful zero-roll from additive old-v28 normalization, and `captured_from`
with world namespace/spawn ID/generation. Runtime fields are projections,
not a second persisted store. Normalize legitimate absent fields before
all admission validation; present malformed fields still refuse.

Host combat cards are rebuilt from `Session.admitted_character_state`,
with the exact deployed owned UID and canonical Best/relic state, before
trait dispatch. Foundation must retain its current-generation actor/body
binding. Canonical utility healing requires `view.host_trait_row` built
from that same admitted UID; no client field may supply it. Apply modifiers
before action timing, costs or heal receipts are staged, once only.
