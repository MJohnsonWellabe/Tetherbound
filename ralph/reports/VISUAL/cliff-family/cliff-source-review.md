## Terrain shader and Veilfall

- `coastal_rock_material.gd:22–58` uses world-position geometric derivatives for its steepness mask, signed side projections for colour and normals, then projects detail onto the smooth rendered normal. The resulting `(tangent, normal, binormal)` storage matches Terrain3D's later `.xzy` normal-map decode. A neutral texture preserves the smooth surface normal.
- CPU mathematical reproduction, deterministic seed 941: 10,000 upward-hemisphere slopes with both signed X/Z directions and randomized valid tangent normals. Maximum neutral error and world/basis round-trip error were both `5.55e-16`; minimum detail/surface-normal dot product was `0.6929014575`. Signed plane bases have `cross(T,B)` equal to the corresponding signed axis. These are double-precision mathematical checks, not shader compilation or GPU precision evidence.
- The layer runs after accumulated material normalization. It leaves height/control sampling, vertex geometry and collisions untouched. At normal Y >= 0.68, world Y <= 0.2, or within Veilfall's configured 430 m radius, the write branch is skipped. Its roughness still receives Terrain3D's later colour-map wetness adjustment.
- Water installs coastal first; `water_veilfall.gd:219` subsequently reads the existing shader and appends its independent tail. Their anchors/markers do not conflict. Veilfall's mask is zero outside radius 430, while coastal rises from zero over radius 430–460, so their masks do not overlap with current settings.
- Native verification should read both markers **and** coastal sampler/strength plus Veilfall radius after the final installer. The new receipt checks marker presence only; source alone does not establish that Terrain3D retains every custom uniform through the second override toggle. This is a verification limitation, not an observed lost-uniform defect.

## Candidate 2 follow-up — painted rock and three-plane projection

Reviewed the updated coastal helper and `water_visual.json` on 2026-09-27. Cloudreach source is unchanged. **No new source/math blocker found.** The earlier coastal statements about all gentle ground being unchanged and four texture reads are superseded by this section.

- The new mask correctly decodes base ID from bits 27–31, overlay ID from bits 22–26 and blend from bits 14–21, matching Terrain3D's own decode. It computes authored ID 2 occupancy as `base_is_rock * (1-blend) + overlay_is_rock * blend`. Both IDs equal to rock produce one; neither produces zero. With bilerp it uses the same four control samples and spatial weights; without bilerp it uses sample 3. It adds no control-map texture fetches. The current texture array confirms ID 2 is rock, and Water still explicitly disables automatic texture selection.
- CPU exhaustive encode/decode probe covered all **262,144** base/overlay/blend combinations, including high unsigned IDs and varying unrelated low control bits: maximum occupancy error `1.11e-16`. **10,000** randomized four-corner bilerp cases compared the shader expression with independently aggregated per-ID paint weights: maximum error `2.22e-16`. Seed 942. These are mathematical checks, not native control-map readback.
- This is deliberately raw authored paint occupancy, not the final height/sharpness-adjusted contribution from `accumulate_material`. At mixed rock/grass boundaries it can therefore differ from the visible stock blend. That is a changed material transition to inspect, not a decoding defect. Painted flat rock now changes; gentle ground with zero rock occupancy remains unchanged. Height/collision, the waterline mask and the Veilfall exclusion are unchanged.
- Y-plane UV is `(world.x, world.z)` with tangent `+X` and bitangent `-Z`, so `cross(T,B)=+Y`. Its world perturbation `(ny.x, 0, -ny.y)` is consistent with the existing signed X/Z planes and Terrain3D's normal convention. This assumes an upward heightfield; it is not a general underside triplanar implementation.
- A second CPU normal probe used **10,000** cases with independent geometric and smooth upward normals, randomized valid texture normals, and all signed X/Z directions. Maximum neutral error `6.66e-16`; basis round-trip error `5.55e-16`; minimum detail/surface dot product `0.7152543966`. Flat Y projection matched the expected `(nx, nz, -ny)` world normal with zero error. No zero-length reconstructed normal occurred.
- Final added sampling cost is **six gradient texture reads per active fragment: three albedo plus three normal**. All six execute in the source even where an axis weight is zero; do not claim an axis-aligned two-read optimization. The raw paint decode/mask executes before the branch everywhere. Candidate 2 also activates the branch over painted gentle rock, so its pixel coverage can exceed candidate 1. Geometry and draw count are unchanged; GPU timing remains open.
- `coast_rock_texture_id` defaults to 2 and is not exposed through the installer's config loop. This is correct for the current fixed Water array but must be updated or wired explicitly if that array is reordered. The earlier uniform-survival/native compilation and controlled-config validation limitations still apply.

No engine/import/export or production edit was performed for this follow-up. Native painted-rock transitions, final shader uniform readback and device cost remain separate verification.
