## Existing overlap diagnosis

`_build_cover_tiers` reads count, centre bias, reach and material values but never reads the old tier `seed`. Its lattice fill also receives no seed. The hash uses world cell plus item/layer tag, not tier name. Lilac/gold therefore share exactly the same hashed positions, yaw and rank wherever their schedules contain the same cell/tag. Both current flower tiers also use drift scale .04 and contrast .93 with the same unshifted noise field. Their different counts/plans, size and density mean they are not universally identical populations. The lilac tier additionally has Ridgeline Watch's local composition mask.

The config prose claiming the old distinct `seed` values separated colour patches is unsupported by this current implementation. Tidewake has one strand-flower tier and no equivalent two-colour overlap problem.

- New seed=0 adds unsigned zero to the existing salts, yielding the identical hash. Offset=(0,0), patch_start=patch_full=0 keep the original `pow(value_noise(world_xz*drift_scale), drift_gate)` mask and skip thresholding. GDScript sets those exact defaults. No count, lattice-plan, slot encoding, tile scheduling, radius or reach change appears in the diff.
- CPU reproduction of the shader's 32-bit hash tested 100,000 cells/tags, including negative world cells, across four salts: **400,000 default comparisons, zero mismatches**. This is an algorithmic equivalence check, not a bitwise GPU image comparison.
- On the same 100,000 cell/tag pairs, candidate lilac/gold seeds produced **zero exact XY matches** after float32 hash conversion. At cell size 2 and jitter 1, mean pair separation was 1.042930 m, RMS 1.154423 m. This establishes useful decorrelation, not guaranteed spacing or collision avoidance.
- The world-cell/tag identity remains the hash input, so camera tile reassignment does not re-roll a surviving item's placement. Ground height/control lookup and built-ground exclusion algorithms remain unchanged and operate at each newly seeded location. A moved flower can consequently pass/fail a different ground mask or exclusion; that is expected sampling at the new position, not a gameplay change.
- The optional controls are technically available to any generic cover tier, not enforced by mesh type. Current candidate overrides target only `Cover_flowers`, `Cover_flowers_gold` and `Cover_strand_flowers`; default bushes/litter retain their prior behavior. ## Claims and numerical limits

The shader comment saying seed changes **only** within-cell placement is too narrow: `cover_rand` also replaces yaw salt 53 and LOD presence-rank salt 71. Scheduling/reach remains unchanged, but the identities and growth of flowers at a fading boundary change. Size/tint/keep rolls also respond indirectly because their existing hashes use the new world position. Describe this as stable per-tier placement/yaw/presence decorrelation.

Offsets produce independently positioned noise fields, not mutually exclusive lilac/gold territories. Some patches can overlap by design; no minimum-distance or colour-exclusion rule exists. `drift_offset` is in noise coordinates after multiplication by scale, not metres.

The `patch_full > patch_start` condition avoids equal/reversed smoothstep edges; otherwise it falls back to the old exponent mask. When enabled, thresholding **replaces**, rather than compounds, `drift_gate`. The current candidate thresholds and positive gate values are finite and valid. Existing authored composition still multiplies the resulting keep mask, preserving Ridgeline's quiet-zone structure while potentially reducing its blooms.

Candidate density_gain 1.4/1.2 is accepted programmatically despite the editor hint range. Values above one saturate the keep comparison in patch cores; they cannot create additional instances. Thresholds with contrast1 allow genuinely empty gaps. The helper assumes `drift_offset` is a two-number JSON array and uses positive practical shader-int seeds; those current inputs are valid.

## Performance and capture limits

No meshes, instances, draws or texture reads are added. The same four lattice hashes receive new salts; one existing noise evaluation gains an offset. The enabled threshold adds a uniform condition/smoothstep; `pow` is still expressed before the branch, so do not claim it has certainly been eliminated by compilation. Changed survival/size can change rasterized area and overdraw even with identical submitted counts. Tile bounds need no expansion for seed jitter, which stays within the existing jitter envelope.

The local harness selects named flower materials, captures sequential baseline/candidate after 24 frames and restores prior parameters. It also changes item size, jitter, density and noise scale, so the paired images test the combined candidate, not seed separation in isolation. Animation/time can advance between frames. Its nonempty-material assertion does not prove every expected tier exists; retain the printed material receipts when interpreting each region. No native compile, camera-motion/LOD sweep or frame-time test was run in this review.
