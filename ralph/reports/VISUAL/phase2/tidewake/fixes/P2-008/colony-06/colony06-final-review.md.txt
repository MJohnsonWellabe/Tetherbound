1. **Pair acceptance does not check actual camera orientation.** `_capture_row` resets requested yaw/pitch and checks final player/camera positions, but does not compare the recorded `camera_transform.basis_*`. The inherited capture keeps the production rig processing. `camera_rig.gd::_process` still runs look input, tracking and impact roll; roll can change image orientation without moving the lens beyond the 5cm threshold. A materially different view can therefore pass the current pair check. Compare the recorded camera basis directions or quaternion angle with a small explicit tolerance. Also record/check per-frame FOV/projection settings if permitting any production camera profile changes; the initial manifest FOV alone is not a per-frame observation.

2. **Process-stop failure can bypass final cleanup.** The runner's outer `finally` performs `Stop-Process`/`WaitForExit` before entering the nested `try/finally` that restores/checks state and releases the token-owned lock. If the process exits between `HasExited` and `Stop-Process`, or stopping it otherwise throws under `$ErrorActionPreference = 'Stop'`, APPDATA restoration and lock cleanup are skipped. Put the process-stop attempt inside a `try` whose `finally` unconditionally restores APPDATA and performs existing token-checked cleanup. Do not release a foreign token or suppress a genuine termination failure.

The rest of the reviewed design is suitable for a bounded diagnostic attempt. Shader mutation targets the preloaded production Shader object, preserves its identity, and verifies that the actual live GrassField material and material override use that object. Code hashes are checked before frames; the wrapper does not manufacture a baseline when binding fails. The candidate default lookup first checks the material, then the RenderingServer shader default, and rejects null/wrong .18 values. Uniform retention is not assumed for the listed config parameters: each is checked against the mounted 05 config and then compared between pairs. This cannot prove compiled GPU behavior before rendering.

The mesh check covers both tiled and untiled GrassField layouts: only nodes sharing the verified grass material count, and their instance-count sum must equal `_ring_instances`; mesh and MultiMesh IDs/counts must remain identical within each pair. No mesh/count setter occurs in the wrapper. Source/config/pack hashes and false disk gates are checked, fresh output/APPDATA is required, a unique lock token is used, and ordinary completion restores the original in-memory shader. Failed capture records do not produce an accepted complete run. Persistent production files are never rewritten.

## Bounded fixes completed

Both findings above are now resolved in the scratch wrapper/runner. The wrapper explicitly snapshots actual camera global transform, FOV, projection and keep_aspect during the final settled/draw verification. It compares each basis component with a maximum absolute numerical delta of 1e-6, checks FOV/projection/aspect exactly, and retains the 0.05m player/camera position tolerances. The comparison uses its own grass_verification camera observation rather than assuming the parent record contains a camera transform.

The runner now places the stop/wait attempt inside an unconditional cleanup finally. APPDATA restoration and production checks run even if termination raises. Lock release additionally requires a confirmed exited owned process (or no process started); alive or uncertain state retains the token. A Stop-Process race is accepted only after the same process handle confirms exit. Genuine termination failure propagates, and foreign tokens remain untouched.
