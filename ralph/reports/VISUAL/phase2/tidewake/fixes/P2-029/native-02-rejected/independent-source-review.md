The wrapper appends a sample observation immediately after the draw wait and before validation can return. It records the actual monotonic time, elapsed/lateness values, camera transform/lens/delta, current viewport camera, player transform/velocity/floor state, rig transform/local camera, spring lengths, follow/retarget values and target transform, physical body and rest receipt. Lifecycle entry also records the corresponding capture context. On rejection it saves `rejected__<frame-id>.jpg`, records dimensions/save status/hash, copies validation failures, and checkpoints before returning. This path never appends an accepted frame. Empty images or save errors remain explicit failures; source cannot guarantee that an image write will succeed.

Timing and endpoint validation now happen before the accepted image/frame path. This prevents a failed timing/endpoint sample from first entering `_records`. Camera/body/light failures likewise retain their observation and separate diagnostic image. The shared observation Dictionary is subsequently marked accepted only after successful accepted-frame append; the final checker requires 14 accepted, failure-free observations in addition to 14 expected frames. A rejected diagnostic does not satisfy either count.
