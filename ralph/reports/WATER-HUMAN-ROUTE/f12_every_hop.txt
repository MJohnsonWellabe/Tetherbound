Method and fixtures
- Hops: the route's from_anchor, each rest_anchor_id in order, then to_anchor. A route with
  no rest anchors has one hop.
- Hop path: the authored route polyline between those stops, including any non-rest bend
  vertices and the shore-exit points. It is not a straight chord.
- Steering: seven alternating lateral offsets at equal arc-length stations, then the hop end.
  The amplitude is solved so the commanded length is 1.155x the authored hop path. The run
  asserts that ratio is between 1.14 and 1.17. Where the path bends, the ratio against the
  straight chord is higher (up to 1.228). Movement uses real move_forward input and camera
  yaw; there is no position scripting.
- Position writes: one per hop, onto the hop's dry start anchor on baked terrain. For hops
  after the first, the actual arrival was already within 0.35-0.43m of that anchor
  (start_snap_m). The run fails if that distance exceeds 1.0m.
- Stamina: before each hop the player stands dry until stamina equals max (bounded at 900
  frames). In every hop the refill had already happened while walking up the shoal and
  settling, so regen_frames=0. max_stamina is asserted to be 100 at every hop start. No
  Heart multiplier applies.
- Level 0: swimming skill XP is cleared after every movement frame, so drain stays at level-0
  efficiency. This is conservative because earned levels only reduce drain. The minimum
  efficiency is asserted to be 1.0000. The fixture also asserts the player is not mounted.
- Departure current: the route's required_departure_flag is set as a fixture, the same as
  the single-hop mode. This does not prove the story objective was earned.
- Assertions per hop: at least 20% minimum stamina while swimming; the hop entered swimming;
  it ends dry (on floor, not swimming); health unchanged; the hop end's authored safe
  landing earned. After the final hop, dry-land regen is continuous and bounded, and the
  per-frame stamina gain stays within the configured regen.

PARTY FINDING (honest): the fixture party is EMPTY (party_size=0). Game.reset_for_new_game()
creates PARTY.new() with no members, and the smoke adds none. It is not the original five
starters/companions. Human swimming (swim_controller.gd physics_step / swim_state.advance)
reads the party only to save an active swim mount, so an empty party and the original
five with no swimmer drain identically. Still, this run does not literally instantiate
the original five.
