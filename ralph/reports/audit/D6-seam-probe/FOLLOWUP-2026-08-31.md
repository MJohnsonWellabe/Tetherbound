# D6 dashed terrain seam — mip/filter follow-up probe, 2026-08-31

**Diagnosis only, no fix applied.** This is the "one more probe (mip/filter)"
`BACKLOG-D6-SEAM-PROBE` names as the closing cost, run per the audit's own
`ralph/reports/audit/D-2026-08-31.md` D6 finding. Reuses the same fixed
camera as `tools/_audit_d_seam_probe.gd` (band-1 opening stand, EYE_XZ
(8,90) -> AIM_XZ (-40,180)), one frame per configuration, camera never
moves, so a pixel diff isolates exactly what each change moved.

## What the predecessor probe already ruled out

`tools/_audit_d_seam_probe.gd`, this session: changing Terrain3D's clipmap
(`mesh_size`/`mesh_lods`) did not move the line at all. Clipmap ruled out.

## What this probe tested, and the result

Two new tools, both committed:

- `tools/_audit_d6_mipfilter_probe.gd` — 3 frames: shipped config, per-tile
  detiling forced to 0.0 rotation/0.0 shift on all 6 ground textures, and
  `mipmap_bias` forced to 1.5 (the top of its `hint_range(0.5,1.5)`, the
  heaviest blur that uniform can express).
- `tools/_audit_d6_debug_overlay_probe.gd` — reads Terrain3DMaterial's five
  debug-overlay flags (`show_region_grid`, `show_vertex_grid`,
  `show_contours`, `show_navigation`, `show_instancer_grid`) and captures
  with them forced off.

**Result: two of three sub-hypotheses ruled out, one CONFIRMED as a real,
if partial, cause.**

1. **Debug overlays: ruled out.** All five flags read `false` already
   (`seam-probe-overlay-asfound.png`/`-forcedoff.png` in `shots/audit-d6/`,
   not committed — the live values printed to the run log are the evidence:
   `{show_region_grid: false, show_vertex_grid: false, show_contours: false,
   show_navigation: false, show_instancer_grid: false}`). Not the cause.

2. **`mipmap_bias` (generic mip/LOD blur): ruled out.** Forcing it to 1.5 —
   heavier blur than the shader can otherwise express — left the line
   visually and structurally unchanged. Compare
   `seam-probe-mip-default-crop-isolated.jpg` and
   `seam-probe-mip-biashigh-crop-isolated.jpg`: same dash density, same
   contrast, same position. Whatever produces the line, it is not "the wrong
   mip level is being blurred in."

3. **Per-tile detiling rotation: CONFIRMED as a major, though not sole,
   contributor.** `shaders/terrain_ground.gdshader::accumulate_material()`
   gives every texture tile (spacing `1/uv_scale` — 4m for the path texture
   painted at this stand, 5m for grass/soil) an independent random UV
   rotation (`_texture_detile_array`, keyed by `random(uv_center)`), and
   rotates the anisotropic filtering derivatives (`id_dd`) to match. Two
   adjacent tiles get different random rotations, so the anisotropic
   footprint used to filter the SAME texture array is discontinuous at the
   boundary between them — textbook "filtering mismatch across a tile
   boundary," just implemented via a per-tile rotation rather than a simple
   LOD switch. Forcing `detiling_rotation`/`detiling_shift` to 0.0 on all six
   `Terrain3DTextureAsset`s makes the dashed line drop from a dense, high-
   contrast dashed run to a handful of faint, barely-visible dots over the
   same path. Compare `seam-probe-mip-default-crop-isolated.jpg` against
   `seam-probe-mip-nodetile-crop-isolated.jpg` — same crop box (820,510)-
   (1000,555), same camera, same lighting, nothing else changed.

A faint residual line survives even with detiling fully off (visible as pale
dots in `-nodetile-crop-isolated.jpg`). That residual is NOT explained by
this probe. It is not the control map either — `ralph/reports/
handover-T1-GROUND-3-2026-08-30.md`'s own probing already ruled that out
("it is *not* the sin-hash, *not* the control map, and only partly the far
cover"), and this session's clipmap probe ruled out `mesh_size`/`mesh_lods`.
So after this probe, the named-and-eliminated list is: clipmap, control map,
sin-hash, generic mip-bias blur, and debug overlays — with detiling's
per-tile rotation now confirmed as the dominant real contributor and
something else, still unnamed, behind the faint remainder. That remainder is
a hypothesis for the next probe, not evidence gathered here.

## Evidence

All in this directory, all from the fixed camera above, `capture_check.gd`
passed on every shutter (grass field bound and drawing):

- `seam-probe-mip-default.jpg` / `-nodetile.jpg` / `-biashigh.jpg` — full
  1280x800 frames, for context (same composition as the predecessor probe's
  `seam-probe-default.jpg` etc. — boulder, treeline, grass all match,
  confirming the camera never moved).
- `seam-probe-mip-{default,nodetile,biashigh}-crop-isolated.jpg` — the
  decisive comparison. Same crop box (820,510)-(1000,555) in the source
  frame, 6x resample, chosen specifically because it isolates the dashed
  line from the unrelated macro-shading blotch that sits over part of the
  wider frame. `default` and `biashigh` show the same dense dashed line;
  `nodetile` shows it almost gone.

A first attempt at a numeric confirmation (sampling perpendicular intensity
profiles along an estimated line path and measuring dip depth) came back
inconclusive — flat across all three configs — but that measurement's line
path was hand-estimated from two endpoints and is almost certainly missing
the true sub-pixel-thin dash locations by enough to sample the surrounding
mottled texture instead. The tight, same-box visual crops above are the
reliable evidence; the failed numeric attempt is noted here so a future
session doesn't re-trust a "flat" automated diff over what the frames
actually show.

## What a real fix needs (not attempted this session)

Detiling cannot simply be turned off — it exists specifically to break up
the 2K ground textures' own repeat period (`_comment_detiling`,
`data/config/terrain_playground.json`: "Together with the shader's macro
variation, this is what separates 'ground material' from 'wallpaper'").
Removing it reopens the tiling complaint it was built to fix.

The fix has to smooth the DISCONTINUITY at the tile boundary rather than
remove the per-tile rotation itself — options for whoever picks this up:

- Cross-fade the UV rotation angle across a narrow band straddling each tile
  boundary (blend `id_detile` between the two neighbouring tiles' random
  values near `uv_center` edges) rather than switching it in one texel.
- Clamp derivative rotation specifically (leave UV rotation as-is, only
  soften how sharply `id_dd` is allowed to change across the boundary), if
  the aliasing is coming from the anisotropic footprint rather than the
  albedo/normal sample itself — worth confirming with a probe that holds UV
  rotation fixed and only zeroes the derivative rotation, isolating which of
  the two `accumulate_material()` moves is actually responsible.
- Investigate whether Terrain3D's upstream shader template has a newer
  detiling implementation that already handles this (the shader here is a
  pinned auto-generated dump, `shaders/terrain_ground.gdshader`'s own header
  explains how to regenerate it).

Any of these needs its own render + `visual-judge` pass per
`ralph/conventions.md` before landing, since it touches ground presentation
directly.
