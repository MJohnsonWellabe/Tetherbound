## G1 — The next serious challenge is usually clear

*Source: FUN §21.1.*

**The test that decides it.** Two mechanisms carry this: (a) `quest_log.gd::
guided_entries()` shows what is DONE plus the ONE current rung, never the
full 24-entry list (`data/progression/objectives.json`'s own
`_comment_no_spoilers`); (b) a pre-fight readiness line at every rung of
spec §3's ten-fight challenge ladder, sizing the next fight in the
conversation the player already reads before it.

**Verdict: PARTIAL.** The mechanism is real and complete for all ten rungs;
whether it reads as "clear" to an actual player through a continuous run is
unverified.

**Evidence.**
- `ralph/reports/finding-ladder-readiness-2026-08-29.md`: all ten rungs
  (South Bridge, Warrens Guardian, Captain Vance, all three captains, the
  Hall gauntlet's three fights, the Warden) carry a sizing/rest cue
  delivered in dialogue immediately before the fight it describes. Example
  (Captain Vance): *"Three of mine, and I don't send the weakest out first.
  If your five are still worn from the walk up here, that was the place to
  fix it, not this one."*
- `tests/test_trainers_data.gd::test_the_wider_ladder_carries_its_own_
  readiness_signal` (confirmed present at 453107fb, `tests/
  test_trainers_data.gd:698`) pins all ten against the live dialogue table.
- `objectives.json`'s `how` field (one line per rung naming the concrete
  next action and the bound controller verb, device-aware) covers all 32
  rungs as of T5-STORY-2 — confirmed the guided view still shows one rung
  at a time via `_comment_guided`.
- Access gates reinforce clarity structurally: `road_gate_open`,
  `south_bridge_open`, `hall_approach_open` are real flags
  (`scripts/world/playground_world.gd:209`, `road_gate.gd`) — the player
  cannot wander past the next serious fight by accident, because the world
  is physically closed until it is beaten.

**What this audit could not check.** Whether a first-time player, reading
these lines once mid-fight-prep rather than as an itemised list, actually
forms a clear mental model of "what's next and how hard." That is a
played-path/human-playtest question. `ralph/reports/PLAYTHROUGH-2026-08-30.md`
(T5-PLAY) is the only continuous-save run on record and it stopped inside
S03 (the village), before the first of these ten rungs (South Bridge) is
even reached in its own chain — so no run has yet observed a player meeting
even the first readiness signal in context.

**Closing cost.** Zero further authoring — the mechanism is built and
tested. Closing the verdict to PASS needs a continuous fresh-save run
reaching at least South Bridge and ideally a captain fight, which is
`GATE-F-FULL`'s job, not this lane's.

## G3 — Catching stays relevant to the last hour

*Source: FUN §21.3.*

**The test that decides it.** `tools/_probe_catch_rate.gd` (a played-input
instrument driving the real aim/throw/resolve loop) for the mechanical
half; `data/config/spawn_tables.json`'s `roll_new_worlds` flag and
`spawn_tables.gd::plan_for` for the "stays fresh late" half.

**Verdict: PARTIAL.** The core catch mechanic was measurably broken and is
now measurably improved; the system built to keep catching interesting
late-chapter (rolled/random encounter population) is real, tested, but
**shipped inert**.

**Evidence — the mechanic itself, fixed this cohort.**
`ralph/reports/handover-T5-FEEL-2026-08-30.md` (OP-0830-5, owner: *"catching
is way too hard"*): root cause was `catch_math.accuracy_bonus()` dividing
placement by `body_radius` alone, saturating the clamp on 77% of landed,
on-target throws (median real placement 0.375m against a 0.325m radius).
Fixed to grade over the full hit envelope (`body_radius + orb radius`).
Measured, same probe, same species, same seeds:

| tier | before | after |
|---|---|---|
| 50% HP, aim converged on body | 17.6% | **42.9%** |
| 50% HP, 2.5° aim error | 25.0% | **33.3%** |
| Full HP, 2.5° aim error | 11.1% | **5.3%** (small sample, ~19 throws; flagged, not chased by this audit) |

Pooled at the tier a player actually throws from (50% HP): **21.2% → 37.9%**
catches per throw.

**Evidence — the late-chapter freshness system exists but is OFF.**
`ralph/reports/handover-T3-ENCOUNTER-2026-08-30.md` built a full weighted
rolled-population director (208 of 266 clusters opted in, habitat/weather/
region hard-gated, alpha separation, scarce caps) — but
`data/config/spawn_tables.json:5` ships `"roll_new_worlds": false`, and
**this audit re-confirmed it is still false at 453107fb**:
```
$ grep -n roll_new_worlds data/config/spawn_tables.json
5:  "roll_new_worlds": false,
```
`ralph/START_HERE.md` and `DARK_FEATURES_INVENTORY_2026-08-30.md` (E1) both
record the precondition: the owner wants it on, but only after Gate F
re-baselines against a rolled world, which has not happened. So the
shipping game is the **static, fully-authored world** — every wild
individual a player can find on a repeat playthrough is exactly the one
that was there the first time. For a genuine first clear this is invisible
(the player has no baseline to compare against), but it means the
mechanism spec §21.3 most obviously points to for keeping late-chapter
catching fresh is not live in the shipping build.

**What this audit could not check.** Whether catching a *specific*
individual (rather than a species) still feels worth doing in band 4/5,
where G4 below finds zero new species are introduced — the "stays relevant"
half of this item is entangled with G4's finding.

**Closing cost.** The catch-rate fix is done. `roll_new_worlds` flip is an
explicit owner-directed, Gate-F-gated decision (D-0830-1) — not a defect,
a precondition not yet met; closing it costs a Gate F re-baseline run, which
this audit does not have the mandate or the evidence to perform.

## G5 — Major fights test different aspects of the five

*Source: FUN §21.6.*

**The test that decides it.** `ralph/reports/handover-T3-MATCHUPS-2026-08-30.md`'s
own measured harness, which mirrors `combat_math.gd`/`progression.gd` over
the real trainer/type data, then was re-pointed at the shipped
`data/config/type_chart.json` and asserted byte-identical.

**Verdict: OPEN**, on the typing axis specifically — the axis the spec
language most directly names.

**Evidence.** The five new types (Fire/Electric/Ice/Psychic/Dark) shipped
this cohort change **0 of 27** authored trainer rungs, for all three
starters:

> *"+0% on 27 of 27 rungs, for all three starters."* Per-starter exchange
> ratio unchanged to three decimals. The Warden fight is **bit-for-bit
> identical** — all fifteen multipliers, all fifteen hits-to-kill, unchanged.

Root cause, confirmed by the same handover's own census: **zero** dual-typed
creatures exist on any of the 27 authored trainer rosters (only bands'
*wild* spawns carry the four dual-typed aspect variants), and trainer
creatures can only throw ground/water/air moves — the three types the chart
never touched. `test_no_trainer_roster_creature_is_dual_typed` (present,
pins this as an invariant) means this is not an oversight waiting to be
fixed by future roster edits; it is the current authored shape by design.

This is a narrow but real reading of G5: the type-matchup axis of "testing
different aspects of the five" does not move across the entire authored
ladder. **Other axes this audit did not check** — team size (South Bridge:
2 vs the Hall gauntlet's escalating threes; the Warden's five), terrain,
status effects, or move variety — may still differentiate fights; this
audit's evidence only speaks to the type-chart axis, which is the one the
matchups design work itself measured and is silent on the others.

**Closing cost.** This is flagged by T3-MATCHUPS's own author as a
roster-rebalance question ("a separate pass is under way" per that
handover §6.6) rather than a matchups-system defect — the chart is correct
and complete; the trainer *rosters* are what keep the ladder monotype. A
future roster-diversification pass (T3-TYPECHART's own flagged 57.6%
Ground census) is the lever, not a code or chart change. Sizeable — touches
every band's `trainers.json`.
