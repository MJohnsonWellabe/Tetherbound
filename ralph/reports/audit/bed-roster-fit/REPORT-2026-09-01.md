# BACKLOG-VISUAL-BED-ROSTER-FIT — 2026-09-01

Corrective redo of `ralph/VISUAL-BED-FITS-CREATURE` (merged to `main` at
`6f54c6a8`), which fixed Terrapup's own bed-pose flip but never checked the
rest of the roster and never checked any species at its CURRENT (post
OD-0901-1/2 "grow the ceiling") size. The owner rejected the previous fix
outright ("so is solution was to make terrapup stand in bed again?") and
separately confirmed the wider defect by eye: "galecrest goes way out of the
bed." Full instructions: `ralph/OWNER_DIRECTIVES_2026-09-01.md`.

## Method

New tool, `tools/_measure_bed_roster_fit.gd`, spawns every species in
`data/creatures/species.json` exactly the way `creature_bed.gd::
_sync_rest_body()` does (same `REST_ANCHOR`, same `rotation.y = PI * 0.5`,
same `play_rest()` call a real bed occupant gets), measures the model's
render-space AABB (`render_bounds.gd`, the same trusted bind-pose method
`tools/_diag_rest_roll_math.gd` already used), and checks all 8 AABB corners
against the bed's rim as a true ELLIPSE rather than a bounding rectangle — a
long diagonal creature can pass an x/z-extent check while a corner still
pokes past a genuinely round-ish rim. Headless, no GPU needed, so this can run
in a few seconds per species and be re-run at any candidate rim size.

A second new tool, `tools/_capture_bed_species.gd`, generalizes the existing
`tools/_capture_creature_bed_rest.gd` (hardcoded to terrapup) to any species,
and can override `rest_roll_deg` in-process (mutating
`creature_species.gd`'s cached table, never touching disk) to sweep candidate
roll angles without editing data for every trial.

## Fix: grow the bed (per OWNER_DIRECTIVES_2026-09-01.md, "grow the ceiling")

`scripts/build/creature_bed.gd`:

| constant | old | new |
|---|---|---|
| `RIM_RADIUS_X` | 1.55 | **2.40** |
| `RIM_RADIUS_Z` | 1.35 | **2.05** |
| rim ellipse (diameters) | 3.10m x 2.70m | **4.80m x 4.10m** |
| `PAD_SCALE` | (1.75, 0.72, 1.05) | **(2.71, 0.72, 1.60)** |
| `RIM_BRANCHES_PER_COURSE` | 20 | **30** |

`PAD_SCALE.y` (thickness) is untouched — same discipline as the 2026-08-31
pass: the complaint is footprint, never height. X/Z grow by the same ratio as
the rim (~1.55x / ~1.52x) so the pad keeps tracking the rim's own centreline
the way the existing comment describes; branch count scales with the bigger
circumference so spacing doesn't open gaps.

2.40/2.05 was not picked to exactly clear one species — it was found by
sweeping candidate sizes against the full-roster measurement (2.2/1.8 →
2.3/1.9 → 2.35/1.95 → 2.4/2.05) until every species passed with real margin.
**Every one of the 25 species now fits, worst case (Terrapup's new lying
pose, see below) at 0.97x the rim radius** — comfortable, not a knife's edge.
A single bed size was used rather than a size-tiered bed: the resulting
disparity (Pipwing at 0.23x rim radius up to Veridian at 0.96x) reads as
"generously sized nest," not absurd, in the actual renders below, so the
tiered-bed escape hatch the brief allowed for was not needed.

## Finding 2 / Fix: Terrapup's crouch was never a real fix, and a real one exists

The owner rejected the prior pass's `rest_roll_deg: 0` (a crouch/sit pose,
`play_faint()`) outright — it was never "lying down," and presenting it as
fixed was the thing the brief for this pass explicitly said not to repeat.

This pass swept intermediate roll angles (-30, -40, -45, -50, -60) instead of
only testing 0 and the broken default 90. **-45 degrees genuinely settles
Terrapup onto its side** — the front paws (lifted toward the chest in idle,
the reason the 90-degree default flips it onto its back) land close to where
a real curled sleeping pose puts them at a shallower roll, rather than
swinging wide. Verified by render from two angles and top-down, not
by geometry alone:

- `shots/terrapup-current-front.png` — OLD shipped pose (crouch/sit, the
  owner's rejected "fix")
- `shots/terrapup-roll-45-front.png`, `shots/terrapup-roll-45-far.png` —
  NEW pose, genuine lying-on-side
- `shots/terrapup-final-front.png`, `shots/terrapup-top.png` — final result
  in the grown bed, comfortable margin

Cost: the -45 pose's AABB (2.98m x 2.98m) is meaningfully bigger than the old
crouch's (1.92m x 2.30m) — a partial roll inflates the axis-aligned bounding
box versus either the fully upright or fully flat cases. This is the real
tradeoff the brief anticipated ("if a real lying-down pose is achievable,
ship it") and is folded into the bed-growth sizing above, not treated as a
reason to fall back to the crouch again.

`data/creatures/species.json`: `terrapup.placeholder.rest_roll_deg`
`0.0` → `-45.0`.

## Finding 3 / Fix: Trailpup generalizes cleanly, Bramblebun does not

**Trailpup**: same root cause as Terrapup (idle holds paws off the roll
axis's centreline, so the default 90-degree roll flips it onto its back —
confirmed in `shots/trailpup-current-front.png`, mid-flip, paws in the air).
The identical -45-degree fix produces a clean lying pose here too
(`shots/trailpup-roll-45-front.png`, `shots/trailpup-top.png`) — verified by
render, not assumed to generalize just because the diagnosis matched.
`trailpup.placeholder.rest_roll_deg`: unset (default 90) → **-45.0**.

**Bramblebun does NOT generalize**, and it would have been dishonest to claim
it does. Rendering `play_faint()` directly (roll 0, no rotation applied at
all) reproduces the exact same self-intersecting antler/twig tangle as every
rolled angle tried (-30, -45, -60, and the shipped 90) —
`shots/bramblebun-faint-zoom-front.png` vs `shots/bramblebun-current-front.png`.
This means the defect is not a roll-angle/body-plan mismatch at all: this
species' `idle`/`faint` animation clip itself is already broken for its
antler geometry (a plausible bad bone keyframe in the quadruped rigger's
output — its `attack` clip, `ralph/reports/T1-CREATURE-RIG/shots/pose_check/
bramblebun_redesign_attack10.png`, renders cleanly, so the rig CAN produce
sane poses; something specific to idle/faint does not). No roll value fixes
this. `rest_roll_deg: 0` is applied anyway, as the smallest-footprint option
measured (the antlers point up rather than out, and the core body stays
planted rather than being thrown further off-pad by an additional broken
roll) — a **containment** choice, explicitly not a claim that the pose itself
is fixed. Filed separately: **BACKLOG-VISUAL-BRAMBLEBUN-IDLE-DEFORM**, needs
an animation/rig fix, not a data tweak, and is out of scope for a bed-fit
pass.

## Finding 4: Veridian (legendary) needed the crouch escape hatch too

The single worst offender in the roster measurement (1.66x the OLD rim even
in its shipped 90-degree rolled pose — `shots/veridian-roll90-front.png`,
visibly back-flipped, legs splayed, antlers off the pad). Unlike
Terrapup/Trailpup, Veridian's idle plants all four legs near the body
centreline like a real standing stag, so ANY roll (90, -30, -45 all
measured) swings the legs OUTWARD and makes the horizontal footprint *worse*
than not rolling at all (roll 0 footprint: 2.95m x 3.04m; roll -45: 4.63m x
4.63m). `rest_roll_deg: 0` (the same crouch escape hatch as Terrapup's old
fix and Galecrest's existing one) is the smallest-footprint option found and
is what keeps a 3.6m legendary inside a bed of any sane size —
`shots/veridian-faint-front.png` and the final `shots/veridian-top.png` show
it fully contained. This is a real, acknowledged remaining pose-quality gap
(it reads as standing/settled, not lying flat) that a bed-FIT pass is not the
place to chase further — this creature towers over any reasonably-sized bed
regardless of pose.

  fixed for all of them; a full roster pose-quality pass (per-species roll
  tuning or a smarter roll that reads the model's own bind-pose paw
  positions) is real work still on the table.
